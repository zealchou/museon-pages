# 數值與平衡

**這一份是整個專案最不能亂動的地方。** 課程的核心論證直接建立在這裡的三個數字上。

---

## 目標

開場公告，所有人都看得到：

> 這一年，營收要多 28，信任最多只能少 28。
> 兩個都做到才算成功。只做到一個，不算。

對應到指標就是 **營收 ≥128、信任 ≥72**（都從 100 起算）。
刻意設計成對稱的 ±28，講起來好記。

三個指標：

| 指標 | 起始 | 顏色 | 說明 |
|---|---|---|---|
| 營收 | 100 | 墨 | |
| 信任 | 100 | 柿褐 | |
| 內耗 | **0** | **朱紅** | 唯一只會往上；全場唯一的飽和色 |

內耗從零開始是刻意的：**那個數字本來不存在，是他們自己造出來的。**

## 計分公式

### 營收與信任

每一場的影響是**五票的加權平均，不是加總**：

```
delta = Σ(該選項效果 × 該選項票數) ÷ 5
```

除以 5 這件事很重要。早期版本忘了除，結果第一場全員選 A 就 +40 營收，
整局在第一場就結束了。

實作在 `public/index.html` 的主持台推進邏輯：

```js
sc.op.forEach(o => { dr += o.e.rev * c[o.k]; dt += o.e.trust * c[o.k] });
const rev = Math.round(state.rev + dr / 5);
const trust = Math.round(state.trust + dt / 5);
```

### 內耗

只看票數分裂形狀，跟選什麼無關：`5-0`→0、`4-1`→2、`3-2`→4、`3-1-1`→6、`2-2-1`→8。

## 三層對比（課程的核心論證）

| 情況 | 雙達標機率 |
|---|---|
| 五人盲投（第一輪的處境） | **5.1%** |
| 有討論、但沒真的交換資訊 | **23.5%** |
| 攤開角色卡、挑對場次 | **99.9%** |

這組數字講的不是「溝通很重要」，而是：

> **光是「可以講話」，只把成功率從 5% 拉到 23%。
> 真正把手上的資訊攤開來，才是從 5% 跳到接近確定。**

**開會，跟交接資訊，是兩件事。** 這正好是莉凱真正的痛點——他們不缺會議，缺的是完整的交接。

## 單一策略必須全部失敗

| 打法 | 營收 | 信任 | 結果 |
|---|---|---|---|
| 全衝 A | 150 (+50) | 69 (−31) | 信任崩 |
| 全平衡 B | 116 (+16) | 145 (+45) | 營收不足 |
| 全保守 C | 93 (−7) | 121 (+21) | 營收不足 |

**三條都要失敗**，否則遊戲太好破——只要有一種態度能一路走到底，
「必須挑對場次」這個核心就不成立了。

## 怎麼做到 5% vs 99% 的落差

靠**刻意放大變異**：設計出明顯「該衝」和明顯「是陷阱」的場次。

- **該衝場**（R1-1、R1-5、R2-3、R2-5）：A 選項營收高、信任代價小
- **陷阱場**（R1-2、R1-3、R1-4、R2-4）：A 選項營收普通、信任代價巨大

盲投分不出來這兩類，**但知道別人手上有什麼的人分得出來**。
這就是角色卡在機制上真正的作用——不只是氣氛道具。

> 註：30% 是這個格式的結構上限。五人投票會把變異除以 √5，盲投的分布被壓得很窄，
> 協作那端拉不上去。但 5% / 23.5% / 99.9% 這組講出來的故事比 5/30 更利。

## 設計不變式

模擬器會檢查，違反就報錯：

1. **每個選項在兩軸都不能是 0** —— 有 0 會讓那個選項看起來沒有代價
2. **每一場至少要有一個選項營收為負** —— 否則那一場沒有真正的取捨
3. **每一場至少要有一個選項信任為負**

## 改了數值之後

```bash
python3 tools/balance_sim.py --from-html public/index.html
```

會直接從線上那份 HTML 抽出 30 組數值來跑，確保模擬跟實際上線的一致
（而不是跑一份可能已經過期的常數）。

容許範圍：盲投 3.5–7%、隨機路徑 18–30%、知情 ≥95%、不變式全過。
超出範圍會印 ❌ 並回非零退出碼。

**跑掉了就不要上課。** 那三個數字是要在下午當證據講出來的，講錯就是說謊。
