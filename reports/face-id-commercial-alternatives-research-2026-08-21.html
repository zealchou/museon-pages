前案：人臉身份保留生圖研究

結論先行

有一條可行、可商用且不使用 InsightFace 預訓練權重的路線：PhotoMaker V1 + 已授權的 Zeal 多視角參考照 + SDXL。 PhotoMaker V1 的官方程式碼是自有的「stacked ID embedding」：它以微調的 OpenCLIP 視覺編碼器和融合層處理多張輸入圖；官方 V1 demo 明說「we do not perform face detection」。目前主分支的程式也明確把 V1 與採用 CLIPInsightfaceExtendtoken 的 V2 分開。因此不能把 V2 的 InsightFace 限制回溯套到 V1。官方 V1 model card 標示 license: apache-2.0，程式庫 LICENSE 的原文則是：> “PhotoMaker is licensed under the Apache License Version 2.0 except for the third-party components listed below.”

這不是說「任何模型都已經無條件可商用」。最終成品仍須逐項遵守底模、VAE、LoRA、ControlNet 的條款；SDXL base 的 CreativeML Open RAIL++-M 允許商用與 SaaS，但不是 MIT/Apache，且保留特定使用限制與轉授義務。本研究的「可行」是指：**目前可公開核對的核心鏈中，沒有 InsightFace 的非商用預訓練人臉辨識權重，且 PhotoMaker V1 adapter 的官方權重條款為 Apache-2.0；若選用 SDXL 原廠底模並遵守其 RAIL 條款，可作本案商業素材用途。**這不是法律意見；實作前仍要保留每個實際檔案 revision 的條款快照。

相比之下，若標準是「所有核心權重都只採 MIT／Apache／BSD，連 Open RAIL 類使用限制也不要」，本次查證範圍內沒有一條已驗證且即插即用的高身份保留生圖完整鏈：PhotoMaker V1 需要 SDXL 系底模；官方 SDXL 權重是 Open RAIL++-M 而非 MIT／Apache。這是「嚴格全寬鬆」的未滿足，不是 InsightFace 阻塞。

最終單一建議見本文最後一節：先落地 PhotoMaker V1 + 9 張照片整理成多視角 reference sheet；不要採用 V2、FaceID、InstantID、PuLID 或 3D 重建方案。

判定規則與範圍

本案的三層授權檢查

層級 必須檢查的物件 本案判定方式
程式碼 repo、套件、推理 glue 必須有官方 LICENSE；MIT／Apache-2.0／Boost 可進入候選。
預訓練權重／模型資產 人臉 encoder、adapter、landmarker、3DMM、底模、VAE、LoRA、ControlNet 不能從程式碼 LICENSE 推論；每個實際下載檔都需有官方條款。未找到則標記「授權不明，暫不建議」。
訓練資料與用途聲明 模型卡、資料來源、官方限制 就算權重檔標寬鬆，若官方明文限定 research／non-commercial，仍不放行。資料來源未授權並不會因權重標 MIT 自動變得無風險，需如實記錄。

商業判定的用語：「可進入商用實作」表示官方公開條款沒有商業禁止、但仍須守所有下游條款；不是保證法律上零風險。「不放行」表示找到明文非商業條款或實際權重授權未明。「不適用」表示技術不是身份生圖方案，僅能做前處理或品質輔助。

A1. IP-Adapter 原版：不碰 InsightFace，但要分清楚「OpenAI CLIP」與官方實際使用的 OpenCLIP

官方實作與權重鏈

IP-Adapter 原版不是 FaceID 變體。官方 repo 將其定義為 image prompt adapter；一般版把 image encoder 的全域 embedding 當條件，Plus 版用 patch embedding。官方 weights model card 對原版列出：

  • ip-adapter_sd15.bin：「use global image embedding from OpenCLIP-ViT-H-14 as condition」；
  • ip-adapter-plus_sd15.bin：「use patch image embeddings … closer to the reference image」；
  • SDXL 版則使用 OpenCLIP ViT-bigG 或 ViT-H。

程式也直接載入 CLIPVisionModelWithProjection 和 CLIPImageProcessor；在這條正常 image-prompt 路徑沒有 InsightFace import、沒有臉部偵測，也沒有 512-d face embedding。請勿誤選名稱含 FaceID 的權重；它們是另一條受前案阻塞的路。

授權精確判讀

  • IP-Adapter 程式碼：Apache-2.0。 條款第 2 節原文授與「perpetual, worldwide, non-exclusive, no-charge, royalty-free, irrevocable copyright license」。
  • 官方 IP-Adapter weights：Apache-2.0。 model card YAML 為 license: apache-2.0。
  • OpenAI CLIP 程式碼：MIT。 OpenAI LICENSE 原文：「Permission is hereby granted, free of charge … to deal in the Software without restriction」，並列出 use, copy, modify, merge, publish, distribute, sublicense, and/or sell。
  • 但 IP-Adapter 官方 demo 實際指定的不是 OpenAI CLIP 權重。 是 LAION 的 OpenCLIP ViT-H／bigG；其官方 model card YAML 為 license: mit。同一張 model card 又寫「Any deployed use case of the model - whether commercial or not - is currently out of scope.」這是官方用途／安全告示，並非同一文件中的 license 禁止條款；但對「真正商用友善」的內部標準而言，它足以讓 IP-Adapter 原版退為次選。

對本案效果的現實預期

它能保留髮型、眼鏡、衣著、色調和臉部大輪廓；但 CLIP 的一般圖像語義並不是專為人臉 identity metric 設計。提高 scale 會貼近原照與姿勢／prompt 拉扯，降低 scale 則會增加人物漂移。官方 README 也警告預設 CLIP processor 是 center crop，非正方形圖可能遺失中央以外內容。因此它適合「reference sheet + 多輪人工挑圖」而不適合宣稱單張就穩定復現五官。

A2. PhotoMaker V1：前案錯誤不可沿用到 V1

V1 的官方證據鏈

  1. V1 model card 明載兩個 state-dict parts：id_encoder 是「finetuned OpenCLIP-ViT-H-14 and a few fuse layers」，lora_weights 作用在 UNet attention；YAML 是 license: apache-2.0。
  2. V1 encoder 原始碼 的類別是 PhotoMakerIDEncoder(CLIPVisionModelWithProjection)；它把多張 id_pixel_values 的 visual embedding 合併為 stacked_id_embeds，沒有 InsightFace import。
  3. 官方 V1 demo 固定 pm_version="v1"，並逐張直接 load_image()；其操作說明逐字寫：「Although we do not perform face detection, the face in the uploaded image should occupy the majority of the image.」這直接回答本研究的「是否仍依賴 InsightFace 偵測／對齊」：官方 V1 工作流沒有。
  4. 同一主分支 pipeline 只在 V2 分支選用 PhotoMakerIDEncoder_CLIPInsightfaceExtendtoken；V1 分支選用 PhotoMakerIDEncoder。這是可以重現的版本分界，而不是名稱猜測。

商用判定與邊界

PhotoMaker V1 是這次找到最符合目的的方案：它直接服務「多張同一人照片 → 不訓練 LoRA 的客製化肖像」，也不需 FaceID encoder。它不是完全免除其他權重治理：

  • 官方 README 指定它接任何基於 SDXL 的 base model；選擇時要固定使用原廠 SDXL base 或另一個另有明確商用權利的 SDXL compatible checkpoint。
  • SDXL 官方 LICENSE 的原文允許「host for Third Party remote access purposes (e.g. software-as-a-service)」，但同時要求把使用限制帶給後手；它並非 Apache-2.0。其條款也說「The Data is not licensed under this License」。
  • 不加來歷不明的 RealVisXL、CivitAI checkpoint、VAE、ControlNet、LoRA；每一個都會成為新的權利節點。YouTube 自用可先以 PhotoMaker V1 adapter + SDXL 原廠 base + 官方 VAE 的最小鏈開始。

結論：在「不使用 InsightFace」這一題，V1 可放行；在「所有關聯模型均為寬鬆 license」這一題，需如實標示 SDXL 為 Open RAIL++-M，而非粉飾成 Apache。

A3. MediaPipe Face Landmarker：可替代偵測／對齊，不可替代身份條件

Google Face Landmarker 官方文件列出 bundle 組成：face detector、FaceMesh-V2、blendshape predictor；輸出為 478 個 3D landmarks 和 52 個 blendshape scores。其 Face Mesh V2 model card的授權欄原文為「LICENSED UNDER Apache License, Version 2.0」。

它可乾淨地做下列工作：確認九張照片的單一臉／臉大小、以眼角和鼻尖推導 crop 與旋正、記錄正臉／左／右四分之三角度、排除閉眼／強遮擋照，或在未來把同一張多視角 sheet 的臉放在一致位置。它不會輸出「這個人是 Zeal」的 recognition embedding，亦不會自行生成新圖。

因此它可拼進參考照品質控制鏈：MediaPipe landmarker → 人工核對/裁切 → PhotoMaker V1。它不是「把 InsightFace embedding 換成 MediaPipe embedding」；後者不存在，硬接只會另造未驗證技術。

A4. dlib ResNet：權重 CC0，但不是立即可替換的生圖插件

dlib是 Boost Software License；官方 README 的白話結論為「use dlib however you like, even in closed source commercial software」。其 dlib-models 官方 repo為 CC0-1.0，作者對模型檔的原文是「anyone can do whatever they want with these model files as I've released them into the public domain」。dlib_face_recognition_resnet_model_v1 是 29-conv ResNet，約 300 萬張臉、7,485 identities 訓練；README 明列資料來自 FaceScrub、VGG 和網路抓取。

這使它和 InsightFace 不同授權，卻仍是臉部辨識模型。它可在未來用作本地「生成結果與參考照的相似度排序」的研究工具；但本次沒有找到官方 PhotoMaker V1／原版 IP-Adapter 直接以 dlib embedding 取代其 conditioning 的實作或權重。因此不能把「dlib 可商用」錯推成「可直接替換 InsightFace 且身份保留一樣好」。此外，CC0 是模型發布者的權利聲明，不能替 FaceScrub、VGGFace、爬取圖的上游資料權利作保證。

A5. 3D 重建候選：技術路徑不同，但本案不該以它繞過授權

DECA

DECA 官方專案頁說它由單張圖回歸 identity-specific detail、generic expression，並預測 shape、albedo、expression、pose、illumination 和 displacement map。這是 3DMM/FLAME 參數回歸，不是 InsightFace face embedding。

然而 DECA LICENSE把「Model & Software」明確擴及「3D meshes, software, and scripts」，且原文禁止「incorporation in a commercial product, use in a commercial service, or production of other artefacts for commercial purposes」。所以即使只用它產生臉形資料，再用別的生成器畫圖，仍不符合本案。

3DDFA_V2

3DDFA_V2的 repo LICENSE 是 MIT，原文允許「use, copy, modify, merge, publish, distribute, sublicense, and/or sell」。README 指出其使用 FaceBoxes 偵測器、回歸 3DMM 參數，可輸出 dense alignment、3D、pose、UV texture；訓練資料是 300W-LP。

但 repo 的 MIT 明確覆蓋「Software」，README 雖提到 released pretrained weights，卻沒有在找到的官方文字中對 weights/mb1_120x120.pth、FaceBoxes 權重或 300W-LP 另作可商用權利聲明。因此遵守本研究「查不到就不假設」規則：授權不明，暫不建議商用。不要因為程式碼 MIT 就把模型與訓練資料也標 MIT。

EMOCA

EMOCA 官方 README說其接受單張 in-the-wild 影像，重建含表情細節的 3D face；v2 採用了部分 MediaPipe landmarks，並建立在 DECA 上。可是 LICENSE與 DECA 同類：只授予 non-commercial scientific research／education／artistic projects，且明文禁止 commercial product/service/artefacts。不放行。

路線 B：先建立自有多視角參考資料，再使用外觀參考生成

B1. 遊戲捏臉／character creator 在捕捉什麼？

「捏臉」通常不是在資料庫中認出某個人，而是在一個有限的臉部形狀空間中找參數。核心是 3D Morphable Face Model（3DMM）：

  1. 先以許多已對齊的 3D 臉掃描建立平均 mesh，以及 shape、expression、texture 的主成分 basis。
  2. 從一張或多張照片取得 2D landmarks／輪廓、姿態與可見紋理；估計相機內外參與光線。
  3. 最佳化或以神經網路回歸一組係數：shape α + expression β + texture γ + pose + camera + light，使渲染後的 2D 臉與照片吻合。
  4. 遊戲 UI 的鼻高、顴骨、下巴、眼距滑桿，通常就是這些 blendshape／morph target／3DMM 係數的可讀化控制；它不等同一個跨照片比對身份的向量。

DECA 的官方描述正是這條路：從單張圖回歸 person-specific detail 和 expression-dependent detail；3DDFA_V2 的官方 README 則把輸出稱為「3dmm parameters inference」。兩者皆可看作捏臉參數來源，但它們不是 InsightFace 的 ArcFace 類身份辨識模型。

是否仍可能用到被限制的模型？

不是同一類模型，也不必然依賴 InsightFace；但每個實作仍有自己的 encoder、landmarker、3D head model、訓練資料與權重條款。

  • 幾何路徑可用 MediaPipe landmarks（Apache-2.0）或 FaceBoxes 做臉框，再以 3DMM 參數化和 renderer 擬合；此資料流不需要 InsightFace embedding。
  • 一些研究型 3D reconstruction 方法為了 identity loss、crop 或表情估計，會引入 VGGFace2、FAN、face-alignment 或其他預訓練網路。那是另一組依賴，不能因為「不是 InsightFace」就省略審查。
  • 本次三個實作的結果是：DECA、EMOCA 明確非商業；3DDFA_V2 程式碼 MIT、實際 weights 權利未明。故它們不適合本案現在的商業素材工作流。

B2. 3D 實作候選比較表

為何不建議現在先做 3D 臉資料庫

九張照片足以整理多視角 reference sheet，但不保證足以重建可作高寫實生圖的完整 3D 頭部：側面耳朵、髮際、顎線、頸部、鏡頭焦距和光照都會造成不確定性。就算 3D mesh 成功，從 mesh 回到真實、像 Zeal 的 2D 縮圖，還要一個 image generator；那個 generator 仍須接 reference / identity conditioning。這等於多加一層授權與品質風險，未解決目前真正阻塞。

所以 3DMM 是未來「可控角度、角色資產、動畫」的研究方向，不是本案第一個商業落地步驟。

B3. Reference Sheet / 角色設定圖工作流

可行工作流（不做身份辨識）

  1. 盤點與人工挑選。 只在私有 assets/zeal-photos/ 內操作；挑出正面、左/右 30–45°、左/右近側、自然笑、嘴閉合、不同光線；排除多人、濾鏡、強逆光、墨鏡、嚴重遮擋與過度廣角。
  2. 選圖／裁切輔助（可選）。 用 MediaPipe Face Landmarker 標出視角、臉部在畫面比例、眼睛是否可見；由人確認，再作一致化 crop。這一步沒有建立或保存人臉辨識向量。
  3. 建立私有 reference sheet。 將六到九格照片排成前、左右四分之三、側面和表情欄；保留原始照片、版本、拍攝／授權紀錄，但不放到 git、不發布到公開報告。
  4. 生成。 將同一 reference sheet 或少量精選 reference 圖提供給 PhotoMaker V1；若要對照，可用原版 IP-Adapter Plus（非 FaceID）生成相同 prompt。姿勢／構圖控制應優先用有清楚授權的 pose/depth conditioning 元件；對 YouTube 縮圖只生人物，文字與品牌排版由後段處理。
  5. 人工選片與可追溯性。 每張採用圖保存 prompt、seed、reference-sheet revision、adapter/base/vae/control version 與其 license URL；不要把模型的「長得像」當成身分驗證。

是否能繞開 InsightFace 授權？

能，前提是實際選用的是 PhotoMaker V1 或 IP-Adapter 原版權重，而不是其 FaceID／V2 變體，且不在自訂節點裡額外下載 InsightFace。 這條路不是把人臉辨識偷換名稱，而是把「多張外觀照片 → 視覺特徵條件」輸入 diffusion adapter。

乾淨鏈路可以寫成：

私有原照 →（可選）MediaPipe landmarks / 人工裁切 → 私有 reference sheet → PhotoMaker V1 ID encoder → SDXL base → 人工選圖/排版。

在這條鏈中沒有 InsightFace 的預訓練權重。若改為 PhotoMaker V2、InstantID、PuLID 或 IP-Adapter FaceID，就不再是這條鏈。

效果會打折嗎？會，但折在哪裡？

面向 FaceID embedding 方案 Reference Sheet + PhotoMaker V1 / 原版 IP-Adapter
身份錨定 專用臉部 embedding，通常對眼距、鼻形、臉型有較強約束。 由 OpenCLIP＋stacked image condition 表示外觀；V1 有多照融合，但不是 face verification loss。
多角度／姿勢 仍可能失真，但 embedding 對角度變化較直接。 多視角來源可減少漂移；極端側臉、手遮臉、誇張表情較不穩。
五官細節 理論上較有利於保持五官相似。 能保住大輪廓、髮型、眼鏡和服飾語義；瞳形、鼻翼、牙齒等細節要靠多張候選與人工挑圖。
授權 前案五候選皆因 InsightFace 權重受阻。 可完全避開 InsightFace；但必須守 adapter、OpenCLIP、底模與所有附加元件條款。
縮圖實用性 高 fidelity 潛力，但目前不可商用。 對「人像在一側、文字與視覺符號另排」的縮圖可接受；不要承諾每張都像真人攝影。

PhotoMaker V1 比原版 IP-Adapter 更適合本案，因其原始設計就是「一或多張人像 + trigger word 的 personalization」，官方也建議多張輸入提升 ID fidelity。IP-Adapter 原版可作 A/B 對照，不能取代 V1 的主定位。

硬體相容性與實作前驗收（僅規劃，不執行）

本機是 NVIDIA GB10、CUDA 13.0、PyTorch 2.9.0+cu130，且 compute capability 12.1 可能高於部分候選的已驗證範圍。本研究沒有安裝或跑推理，故不能宣稱「可跑」。

項目 已查到的官方資訊 對 GB10 的判定
PhotoMaker V1 README 要求 PyTorch ≥2.0，並稱最低 GPU memory 11G；官方舊建議含 PyTorch/SDXL 的版本世代。 相容性未知。 需要隔離環境 smoke test；不可從 11G 或舊 V100 數字外推 GB10。
IP-Adapter 原版 README pin diffusers==0.22.1，為較早版本。 風險較高。 CUDA 13 / torch 2.9 / SM 12.1 與舊 diffusers stack 可能衝突。
MediaPipe 可跑 CPU／TFLite；只是準備照，不是生成瓶頸。 GPU 相容性不是必要條件；仍需在實作階段驗實際套件。
DECA／EMOCA／3DDFA_V2 多為舊 PyTorch/CUDA 世代；更重要的是前兩者非商業、後者權重不明。 不因硬體好就放行。

若未來批准施工，最低驗收順序應為：

  1. 建隔離環境，不污染現有講課影片產線；先確認 PyTorch CUDA 可用與 SM 12.1 的實際支援。
  2. 建授權 BOM：精確 repo／revision／SHA、LICENSE URL、adapter、base、VAE、任何 ControlNet/LoRA、下載日期；只要一項無公開商用條款即停止。
  3. 只用 Zeal 已授權、私有照片；第一輪固定一張小批次生成，記錄顯存、耗時、warning、輸出 hash。
  4. 用多個 prompt、不同角度、不同表情，人工盲挑可用率；不是挑到一張好圖就宣稱身份保留成功。
  5. 所有上線圖先經 Zeal 本人批准；生成圖不要擅自表述為實拍照。

單一建議：採用 PhotoMaker V1 + 私有多視角 Reference Sheet；暫不做 3D 重建

建議現在採用的唯一主線：PhotoMaker V1 + SDXL 原廠 base + 私有 Zeal 多視角 reference sheet；MediaPipe 僅作可選的裁切／選圖輔助。

理由是它同時滿足目前最重要的三件事：

  1. 避開已確認的 InsightFace 非商業權重。 V1 官方程式與 demo 都證明它不使用 face detection，也沒有 V2 的 CLIPInsightfaceExtendtoken。
  2. 授權可核對。 PhotoMaker V1 adapter 官方 model card 標 Apache-2.0；SDXL 的 Open RAIL++-M 明確允許商用與 SaaS，但須接受其使用限制；這比「只因 repo 是 Apache 就假定整條鏈可商用」更誠實。
  3. 直接對應 YouTube 縮圖需求。 多張 reference 加 stacked embedding 比一般 IP-Adapter 更為人像 customization 設計，且無需把九張照片拿去訓練自訂人臉辨識器或建立 3D avatar。

下一步不是下載模型，而是先完成一張私有的「參考照資料卡」：為九張照片標記角度、表情、遮擋、光線與可用性，並選定 4–6 張作 V1 identity set。接著在得到允許後，建立授權 BOM；只有 BOM 每個權重都被核對、且 GB10 隔離環境 smoke test 成功，才進行小批次生成驗證。

不建議把 3DMM／捏臉資料庫作為現階段替代：DECA 與 EMOCA 明文不可商用；3DDFA_V2 權重及訓練資料商用權利未明；而且 3D mesh 不會自動變成可商用、像真人的縮圖素材。也不建議 PhotoMaker V2、InstantID、PuLID、IP-Adapter FaceID；它們會重新把 InsightFace 授權問題帶回來。

本文件是工程／授權資料整理，不是法律意見。若日後由自用行銷素材擴張為代客、SaaS 或大規模廣告投放，應由法務針對實際下載的檔案版本與使用方式再確認。
