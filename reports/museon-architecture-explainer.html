The Problem

現有 AI 的三個根本限制

今天 90% 的企業 AI 解決方案都在解決「怎麼讓 AI 做更多任務」，卻沒人在解決「AI 怎麼真正認識你的企業」。這是一個架構層的問題，不是功能層的問題。

🫧

每次對話從零開始

無論 ChatGPT 還是一般 Agent 框架，context window 一關，所有訊息消失。下次對話，AI 不認識你，也不記得你的偏好、習慣與過去的決策。

🔧

靜態工具，不會自我優化

你部署了一套 AI，半年後它還是當初那個樣子。OpenClaw、Hermes Agent 等框架提供強大的執行能力，但沒有「向自己學習」的機制。

🎭

服務所有人，等於不服務任何人

通用 LLM 給出的是「對所有老闆都說得通的話」，不是「對你這個在台中做傳統製造業的老闆說的話」。缺乏企業 DNA 的 AI，建議永遠泛泛。

📊

無法積累洞見

每次對話的經驗、決策背景、報告脈絡——這些珍貴的「決策記憶」在現有框架中都沒有沉澱機制，只能靠人腦記住。

⚡

被動等待，從不主動

標準 AI 是問答機。你不問它不動。真正的企業智能應能主動感知對話裡的信號——情緒、決策卡點、知識缺口——而不是等你說出來。

🔄

維運成本全壓在人身上

更新知識庫、調整參數、修復失敗——現有框架都需要工程師介入。真正的企業 AI 應該能做到基礎的自我修復和自我維護。

Architecture

前台 / 中台 / 後台——
三層架構，各司其職

MUSEON 不是一個「超大型 Prompt」，而是一個有明確分工的三層智能架構。每一層解決不同的問題，合在一起才構成「記得你、懂你、為你演化」的能力。

前台 · Frontend

使用者介面層

你與 MUSEON 直接互動的那一層——Telegram DM、群組對話、指令觸發，都在這裡收發。

  • Telegram Bot 通道（私訊 + 群組）
  • 群組多人協作場景支援
  • 指令 (/) 路由觸發
  • 即時回覆目標 < 2 秒
  • 多對話並行互不干擾
中台 · MUSEON Brain ⭐ 核心

智能決策核心

這是 MUSEON 的大腦——讀取快取、理解意圖、分流任務、協調多個 Agent 協作。所有的記憶、洞見、企業 DNA 都在這裡整合。

  • L1 主持人：毫秒分流判斷
  • L2 思考者：深度分析 Agent
  • L4 觀察者：CPU-only 即時記憶
  • Skill Worker：100+ 技能執行引擎

  • Qdrant 向量資料庫（語意搜尋）

Data Flow

一條對話，如何變成
「企業知識基因」

MUSEON 的核心差異不在「有多少功能」，而在「資料如何被處理」。一句普通的對話，在 MUSEON 裡會經歷五個層次的轉化，最終沉澱成帶有企業 DNA 的可調用知識。

1

Raw Data 收集

對話訊息、文件附件、指令輸出、使用者行為模式——所有原始資料在前台層被收集，帶著時間戳、使用者 ID、場景標籤進入管線。這些是未經處理的「事件流」。

對話訊息行為信號 文件附件指令輸出
2

L4 觀察者 — CPU 即時清洗（零 Token）

L4 觀察者以純 CPU 函數（零 LLM token 消耗）進行即時信號掃描：語意分類、情緒偵測、關鍵詞萃取——10 毫秒內完成，不阻塞對話流程。有意義的訊號才進入下一層。

CPU-only < 10ms 零 Token 消耗 信號分類情緒偵測
3

結晶化（Crystallization）——知識從對話中生長

清洗後的資料進入「結晶化」流程——MUSEON 最獨創的機制之一。系統從原始對話提煉出可重用的知識規則、洞見模式、決策教訓，以結構化格式寫入 crystal.db。每一塊結晶都帶有「可信度分數」和「適用場景標籤」。

「不只記住你說了什麼，而是記住這件事背後的規律——下次相似場景出現，直接調用已驗證的判斷，不從零推導。」

知識結晶可信度分數 場景標籤教訓防護規則
4

DNA36 RC 置入——企業基因標記

結晶化的知識在進入向量資料庫之前，會被 DNA36 RC 標記系統置入「企業基因」——36 條核心行為準則（價值觀、決策偏好、溝通風格、領域知識）被嵌入每一塊知識的後設資料。

白話比喻：就像每本菜譜除了食材和步驟，還帶著主廚的口味觀和判斷哲學——DNA36 RC 讓每一塊結晶不只是資料，而是有立場、有偏好的知識。

DNA36 RC企業價值觀 決策偏好溝通風格
5

外部 LLM × 內部 RAG — 企業客製化 Agent 誕生

最終形成「外部 LLM 通用推理能力 × 內部 RAG 企業專屬知識庫」的複合架構。Claude/GPT 提供語言理解和推理，Qdrant 向量資料庫提供企業專屬知識檢索——兩者結合，才有「懂你這個企業」的回應品質。

Multi-Agent Architecture

三層 Agent 分工——
速度與深度不再互斥

懂 Hermes 的人知道「chain 越長越慢」。MUSEON 的解法是把三種職責拆開——讓不需要 LLM 的任務絕對不進 LLM，讓需要深度推理的任務有完整資源。

L1 · 主持人

分流決策者

所有訊息的第一個接觸點。讀取預生成快取（100ms 內）、判斷簡單/複雜、即時回覆或派遣 L2——把 99% 的延遲消化在這裡。簡單問候直接回、複雜任務立刻 spawn L2 背景執行，用戶感覺不到延遲。

回覆目標 < 2s ｜ 預快取讀取 100ms ｜ 簡單訊息直答
L2 · 思考者

深度推理引擎

per-message spawn 的深度 Agent。搜尋向量記憶庫、檢索結晶規則、讀取使用者畫像、調用技能——不在意速度，在意品質。每個對話都有獨立的 L2，互不干擾，支援同時多場對話深度並行。

語意記憶搜尋 ｜ 100+ 技能調用 ｜ 多對話並行
L4 · 觀察者

CPU-only 即時記憶

MUSEON 最獨特的設計之一。L4 是純 Python 函數，零 LLM token 消耗。在 L1/L2 回覆的同時，L4 平行完成記憶寫入、信號更新、偏好偵測、品質調整——10ms 內 fire-and-forget，完全不阻塞主流程。

0 Token ｜ < 10ms ｜ 四步 CPU 觀察 ｜ 永不阻塞
Skill Worker · 100+

技能執行引擎

/指令觸發時 spawn 的專門工作 Agent。每個 Skill 對應一套完整 SKILL.md 規格——Kairos 命理報告、競品分析、DD 盡職調查、時光之書、ESG 報告……100+ 技能各有規格，而且持續鍛造新技能。

100+ 原生技能 ｜ SKILL.md 規格 ｜ 持續鍛造擴充

⚡ 主動信號觸發層——不等你說，它已感知

MUSEON 內建「主動信號掃描」：對話裡的特定詞彙、情緒模式、決策信號會自動觸發對應行為——從調高分析深度到主動推送洞見。這讓 MUSEON 從「被動問答工具」變成「主動感知系統」，是 OpenClaw/Hermes 預設不具備的能力。

情緒偵測決策卡點識別 知識缺口告警主動洞見推送 八原語能量分析
MuseMEM · Memory System

記憶機制——
跨對話的長期認知積累

一般 LLM 靠 context window 記事，窗口一關什麼都沒了。MUSEON 的 MuseMEM 是跨對話、跨 session 的持久記憶管理系統——你說過的事、你的偏好、你的決策風格，都被系統性儲存和調用。

🗂️

五類記憶分庫

使用者記憶 / 回饋記憶 / 專案記憶 / 參考記憶 / 洞見結晶——每類記憶有獨立的信任度分級、過期機制和優先順序，不同類型記憶由不同路徑調用。

🔍

向量語意搜尋

記憶調用不靠關鍵字，靠 Qdrant 向量語意搜尋。「上次你提到想做 ESG 合作」的記憶能被自然語言直接找到，即使你用了完全不同的說法來描述。

📈

EWMA 動態更新

記憶不是靜態快照——透過指數加權移動平均（EWMA）機制，最新互動的權重更高，舊訊息自然遞減，維持「當前最真實的你的樣子」，不因舊記憶偏向而失準。

🌡️

關係溫度追蹤

MUSEON 追蹤每個重要關係的「互動熱度」——久未聯繫的客戶、長時間沒有跟進的商機，系統自動降溫並在適當時機主動提醒，不讓重要關係悄悄冷掉。

🧬

ARES 十層人格畫像

每個互動過的人，MUSEON 都建立從靜態基本資料（L1）到 AI 動態演化的人格軸向（L10）的十層畫像。隨互動深度增加，信心值上升，建議越來越精準。

⚡

快取預生成

高頻調用的記憶（使用者狀態、活躍規則、自我摘要）被預生成為快取檔案，讓 L1 在 100ms 內讀取完成，不拖慢即時回覆速度——效率和深度同時兼顧。

什麼時候用 OpenClaw？

需要快速整合多種外部工具、在 Telegram 群組自動化工作流、或接入廣泛社群 plugin 生態時，OpenClaw 是輕量高效的選擇。

什麼時候用 Hermes？

需要強大的多步驟推理鏈、複雜任務分解、或在代碼層構建自定義 agent 框架時，Hermes 的推理能力和靈活性是核心優勢。

什麼時候用 MUSEON？

需要 AI 真正「認識你的企業」、長期積累知識、主動發現洞見，並且能在沒有持續工程師介入的情況下自我維運和演化——這是 MUSEON 存在的唯一理由。
