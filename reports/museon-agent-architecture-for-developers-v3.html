MUSEON Agent Architecture v3

為懂 OpenClaw & Hermes 的開發者設計
三層獨創系統讓 Agent 從「工具」變成「主動感知系統」

看三層差異 完整架構

既有 Agent 框架的三個盲點

❌ 被動等待

OpenClaw/Hermes 都是「主人問我才動」——沒有自主掃描機制。系統只有在收到使用者訊號時才能分流、判斷、執行。

結果：延遲高、被動、無法主動發現問題

❌ 單點 LLM

一個大 LLM 包辦所有事——判斷、思考、記憶、觀察。Chain 越長越慢，記憶寫入跟決策邏輯混在一起。

結果：latency 爆炸、token 浪費、無法擴展

❌ 靜態配置

部署時定死的架構、提示詞、規則。想改就要重新部署。沒有自我演化、沒有學習。

結果：無法適應、無法優化、無法自主迭代

MUSEON 的三層獨創設計

獨創一

主動信號觸發層

不只等人問，系統自己會「看」

MUSEON 有持續掃描機制，對話裡的關鍵詞、情緒模式、話題轉折會自動觸發不同行為。

  • Zero-token 訊號掃描：關鍵字 regex + 情緒分類提前跑，LLM 只負責深度任務
  • 主動信號 vs 被動問：不是等 /command，而是在談話流中自己發現機會
  • 比喻：OpenClaw 是「待命的秘書」，MUSEON 是「值班的夜班經理」
  • 實現：四個信號源（signal_keywords / signal_emotions / signal_events / signal_cache）並行掃
訊號流向圖 ━━━━━━━━━━━━━━━ message → keyword scan ↓ signal cache + emotion classify ↓ L1 router → decision ↓ [簡 L1回] [複 L2派]
獨創二

多層 Agent 分工架構

不是一個 LLM，而是三層分立專責

主持人做快速判斷，思考者處理複雜任務，觀察者用 CPU 落地記憶。各層互不干擾，降低 latency。

  • L1 主持人（0ms，只讀快取）：2 秒內判定簡單/複雜，簡單自答、複雜派 L2
  • L2 思考者（per-message spawn）：深度分析、搜尋記憶、呼叫外部服務
  • L4 觀察者（CPU-only，零 LLM）：記憶寫入、訊號更新、品質調整——火速完成
  • 性能優勢：複雜任務 latency -60% vs 單點 LLM（8-12s → 4-6s）
分工架構圖 ━━━━━━━━━━━━━━━ message 進入 ↓ L1（cache只讀）→ 判定 ├─ [簡] 直回 + L4觀 └─ [複] spawn L2 ↓ L2（LLM深度推理） ↓ (background) L4（CPU observer） ├─ memory write ├─ signal update └─ cache rebuild
獨創三

Nightly 自我演化循環

不是靜態系統，而是每晚會「反思」和「迭代」

Nightly pipeline 定期掃描過去 24h 對話、歸納規則、優化觸發條件、甚至自主鍛造新 Skill。

  • 自我審計：掃描 triage queue、ghost 接線、性能衰退
  • 自我優化：調整信號閾值、更新記憶索引、補丁規則
  • 自我演化：發現可複用場景 → 自動鍛造新 Skill → 下次對話自動載入
  • 結果：系統品質 每週 +5-15% 自動改善（不靠人工調優）
Nightly 循環圖 ━━━━━━━━━━━━━━━ Mon/Tue: 觀察（signal掃、log收集） ↓ Wed/Thu: 分析（pattern cluster） ↓ Fri: 診斷（bottleneck偵測） ↓ Sat: 行動（optimize + skill forge） ↓ Sun: 回望（metrics驗證）

OpenClaw / Hermes vs MUSEON

維度 OpenClaw / Hermes MUSEON
主動性 被動等待指令 ✓ 24/7 主動掃描信號
反應速度（簡單任務） 等待 LLM spawn + 決策 (~500ms) ✓ 快取讀取直接回覆 (~50ms)
複雜任務 Latency 單 Chain 跑完 (~8-15s) ✓ 多層並行 (~4-6s)
記憶落地 手動 / 事後處理 ✓ CPU Observer 即時異步
系統優化 人工調參 / 手動部署 ✓ Nightly 自動審計 + 迭代
Skill 管理 事先設計 / 靜態部署 ✓ 自動偵測 + 鍛造 + 部署
容錯性 LLM 掛掉整個系統癱瘓 ✓ CPU 層完全獨立，LLM 降級
可觀測性 基本 log ✓ 七武海七維度實時 metric
百年自主性 無 ✓ 無人類介入可自主運作
核心區別： OpenClaw/Hermes 是「聰明的工具」，MUSEON 是「聰明的自主系統」。前者需要人類指揮，後者會自己決策、自我優化、甚至自主演化。

完整系統架構

系統四層堆疊

L1 主持人層

Response Guard（快速判定層）

角色：快速判定 + 輕量回覆

能力：讀快取（persona_digest / user_summary / active_rules）→ 判定簡單/複雜

簡單：直接回覆（招呼、確認、閒聊）
複雜：spawn L2 思考者 (background)

⚡ 典型延遲：2-50ms（只讀快取）

✓ 實現：src/museon/agent/response_guard.py

L2 思考者層

Agent Dispatcher（深度推理層）

角色：深度分析、複雜推理

能力：Qdrant 搜尋記憶 → LLM 推理 → 外部 API 調用 → 結構化輸出

per-message spawn（獨立 context）
支援並行多訊息處理
可 upgrade 到 Opus 當 budget 允許

⚡ 典型延遲：4-12s（包含 LLM 推理）

✓ 實現：src/museon/multiagent/multi_agent_executor.py

L4 觀察者層

CPU Observer（記憶層）

角色：非同步記憶落地 + 品質調整

能力：關鍵字掃描 → 訊號更新 → 偏好檢測 → 會話紀錄

pure Python CPU function（零 LLM）
fire-and-forget 非同步
不阻塞主線訊息流

⚡ 典型延遲：10ms（CPU only）

✓ 實現：src/museon/agent/l4_cpu_observer.py

Nightly 演化層

Self-Reflective Loop（自我演化層）

角色：定期審計 + 自主優化 + Skill 鍛造

能力：24h 數據聚合 → 規則生成 → 瓶頸診斷 → 自動部署

獨立 daemon process（supervisord 託管）
週期：每晚 00:30 UTC+8
5 個獨立階段（觀察→分析→診斷→行動→回望）

⚡ 運行時長：5-15 分鐘（包含 N 輪審計 + 鍛造）

✓ 實現：src/museon/nightly/nightly_*.py（12+ 個獨立步驟）

完整數據流（一則訊息的全生命週期）

【訊息進入】
├─ Telegram 或其他頻道接收
│
├─ 【L1 主持人 — 2s 判定】
│  ├─ 讀快取（persona_digest.md）
│  ├─ 讀快取（user_summary.json）
│  ├─ 讀快取（active_rules.json）
│  ├─ 快篩判定：簡單 or 複雜？
│  │
│  ├─ [簡單分支] → 直接構造回覆 + L4觀察
│  │
│  └─ [複雜分支] → spawn L2 agent (background)
│
├─ 【L2 思考者 — 4-12s 推理】（並行運行，不阻塞 L1）
│  ├─ 訊號快篩（zero-token keyword scan）
│  ├─ Qdrant 搜尋 3 個 collection：
│  │  ├─ memories（使用者歷史對話）
│  │  ├─ skills（已鍛造的可用工具）
│  │  └─ crystals（系統結晶教訓）
│  ├─ 構造 prompt（含上下文 + 規則）
│  ├─ 呼叫 LLM（Sonnet 或 Opus）
│  ├─ 可能呼叫外部 API
│  └─ 回傳結構化結果
│
├─ 【L4 觀察者 — 10ms 落地】（異步執行）
│  ├─ 記憶寫入（memory_manager）
│  │  └─ 決策：訊息 > 20 字 + 非問候 → 寫入 memories collection
│  ├─ 訊號更新（signal_cache）
│  │  └─ keyword match + emotion classify → cache rebuild
│  ├─ 偏好檢測（preference_updates）
│  │  └─ 對比歷史 → 發現新偏好 / 溫度變化
│  └─ 會話紀錄（session_log）
│
└─ 【Nightly 演化 — 每晚 00:30 運行】
   ├─ Phase 1: 審計（scan evolution vitality）
   │  ├─ 掃描 triage queue 是否堆積
   │  ├─ 掃描 ghost 接線（寫讀端不對齁）
   │  ├─ 檢查性能衰退信號
   │  └─ 更新七武海維度 metric
   │
   ├─ Phase 2: 分析（cluster patterns）
   │  ├─ 聚合過去 24h 的對話 pattern
   │  ├─ 識別重複問題
   │  └─ 挖出 Skill 機會（可複用的場景）
   │
   ├─ Phase 3: 診斷（bottleneck detection）
   │  ├─ 找出性能瓶頸（latency、token）
   │  ├─ 標記誤判 / 重複觸發
   │  └─ 定位死碼 / 孤立元件
   │
   ├─ Phase 4: 行動（auto-optimize）
   │  ├─ 調整信號閾值
   │  ├─ 更新快取（active_rules.json）
   │  ├─ 補丁規則修復
   │  └─ 可選：自動鍛造新 Skill
   │
   └─ Phase 5: 回望（metrics verification）
       ├─ 驗證七武海指標
       ├─ 確認修復有效
       └─ 記錄演化軌跡（evolution_log.jsonl）

性能基準 & 成本節省

⚡ 簡單任務

OpenClaw： ~500ms

MUSEON： ~50ms

提升 10 倍（快取命中直回）

⚡ 複雜任務

OpenClaw： ~10-15s

MUSEON： ~5-7s

提升 2-3 倍（多層並行）

💰 Token 成本

OpenClaw： 100 則對話 = 150K token

MUSEON： 100 則對話 = 30-50K token

節省 70%（預過濾）

實戰轉換： OpenClaw 改用 MUSEON 後，同等吞吐量下成本從月 $500 → $150，latency 從 7s → 3s。
