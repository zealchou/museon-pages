大量電子報工具研究

上千筆名單定期寄送時，選什麼工具、做什麼設定，才不會把收件匣當成賭場。

範圍：開源自架電子報工具與 SaaS 對照｜未安裝、未實際寄送、未處理真實名單

核心判斷：自架電子報後台不等於自架郵件伺服器。對約一千筆名單，後台可自架；實際投遞仍應交給 SES、Postmark、SendGrid、Mailgun 等服務，避免自己承擔郵件 IP 信譽與 MTA 維運。

四個開源候選

高效能 · 中高難度

listmonk

AGPL-3.0；2026-08-26 快照約 23,139 stars。高效、自架、需 PostgreSQL。

  • 退訂／退信：有名單退訂狀態；POP3 或 SES、SendGrid、Postmark webhook，可按門檻 blocklist／刪除。
  • 節流／分眾：sliding-window rate limiting、多 SMTP queue；自訂欄位與 SQL 分眾。
  • 投遞：一般 SMTP 即可，不必自架 MTA。
  • 白話難度：需有人把小主機、資料庫、網域、SMTP 接好；首次架設不適合零技術支援。

自動化最全 · 高難度

Mautic

GPL-3.0；快照約 10,392 stars。完整行銷自動化，不只是電子報。

  • 退訂／退信：退訂 token、偏好中心；IMAP 或 webhook bounce management。
  • 節流／分眾：queue、batch、cron、frequency rules；可選／排除多 segments。
  • 投遞：一般 SMTP 或 API transport，官方示範 SendGrid API。
  • 白話難度：像加裝 CRM；資料庫、PHP、queue、cron、備份都要管，沒有技術人員不建議從它開始。

平衡選擇 · 中高難度

Keila

AGPL-3.0（logo／extra 有例外）；快照約 2,192 stars，2026-06 仍有 release。

  • 退訂／退信：double opt-in、List-Unsubscribe；自架搭配 SES 可自動處理 hard/soft bounce 與 complaint。
  • 節流／分眾：有 campaign scheduler、可重用 segment；官方公開設定未查到全域每時／日限速欄位，請另設上游 quota。
  • 投遞：SMTP、SES、SendGrid、Mailgun、Postmark。
  • 白話難度：後台較友善，但自架仍要 Docker、資料庫、HTTPS、DNS、webhook。

成熟傳統 · 中高至高難度

phpList

AGPL-3.0；快照約 869 stars。成熟的 PHP 電子報系統。

  • 退訂／退信：mandatory 退訂連結；`processbounces`、重複 bounce 自動 blacklist。
  • 節流／分眾：queue／process、lists 與 attributes；近期手冊未查到明確時／日限速操作，須實測並由 SMTP 上游設限。
  • 投遞：SMTP 與 AWS SES 設定欄位。
  • 白話難度：要 PHP/MySQL、queue／cron、更新與備份；首次部署與故障排除需要人幫忙。

SaaS 對照

Mailchimp

全代管，能在瀏覽器管理名單、模板、排程、退訂。仍必須驗證自有網域並完成 DKIM／DMARC；高退訂或負面反應可能引發平台審核。

網域驗證 · 退訂 footer

Brevo

同為代管型 Email SaaS，免管主機、queue、SMTP、webhook；官方提供 DKIM／DMARC 網域驗證指引。代價是訂閱費、平台政策與帳號審核。

網域驗證

避免進垃圾信的 9 個實作機制

  1. SPF、DKIM、DMARC 全部完成並網域對齊：建立可驗證的寄件身分。Google／Yahoo 對大量寄件者均要求；Google、Yahoo。
  2. 新網域先暖機：先小批寄給近期互動、已同意的人，逐步加量並監測負面指標；AWS。
  3. 設定時／日上限與 queue：防突發爆量、服務商限額及壞名單快速擴散。
  4. hard bounce、complaint、無效地址永久 suppress：不是只記錄報表；行銷信對 complaint 應立即停止。
  5. 可見且真正有效的退訂＋one-click header：Yahoo 要求兩天內尊重退訂；Google 也要求大量寄件者提供此機制。
  6. 舊名單先重新確認：來源不明、久未互動者不要直接全量寄；只保留重新確認的人。
  7. 分眾：依興趣、來源、語言與互動切群；未互動者另跑 re-engagement。
  8. 自有商業網域、誠實 From／主旨：不用免費 Gmail/Yahoo 偽裝企業寄件身分。
  9. 寄後設停止線：監看 delivery、bounce、complaint、退訂與 spam rate；負面指標升高先停批次再查原因。

千筆舊名單的安全啟動順序

  1. 盤點名單來源與同意紀錄；說不清來源者不匯入行銷名單。
  2. 用寄件子網域完成 SPF、DKIM、DMARC，並在 SES／SaaS 驗證。
  3. 去重、格式檢查；已退訂、hard bounce、complaint 永久 suppress。
  4. 先寄小批、近期互動、明確同意者；每批觀察至少一天再加量。
  5. 每封先寄測試信箱，確認 From、手機版、純文字版與退訂是否真的生效。
  6. 以 bounce、complaint、unsubscribe 決定是否擴量，不是只看開信率。

一句話推薦

完全不寫程式、要最快上手又想盡量降低垃圾郵件風險：選 Mailchimp（或同級 Brevo）＋自有網域的 SPF／DKIM／DMARC 驗證。它免除主機、SMTP queue、退信 webhook 維運，也有退訂與名單狀態管理；前提仍是只寄給明確同意、先重新確認過的名單。
