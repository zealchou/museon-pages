手腳 vs. 副大腦
三個 AI Agent 的本質差異

OpenClaw、Hermes Agent、MUSEON——都能跑工具、有記憶、會演化。
但優化的目標函數不同，帶來的系統行為截然不同。

三句話定位：OpenClaw = 擴充任務通道，Hermes = 任務效能優化，MUSEON = 判斷品質強化。前兩者放大執行力，MUSEON 強化「問題本身對不對」的能力——這是設計哲學的分叉點，不是功能強弱的比較。

差異一：記憶的維度不同 靜態 persona 文件 vs. 六維動態向量
OpenClaw

SOUL.md、IDENTITY.md 是靜態文件。heartbeat 覆寫式更新——每次覆寫而不是累積演化。知道「你是什麼人」，但不記「你怎麼做決定」。

Hermes Agent

USER.md + SQLite 記錄偏好，可掛 Mem0 等向量服務。記「你喜歡什麼格式」，但偏好是外掛的，不是系統內生的。

MUSEON

ANIMA 裡的 trait_dimensions 是六個 0–1 連續值的向量（溫度、直接度、主動度、深度、自主度、反思度），每次互動後梯度更新——不是「記下你說了什麼」，是「更新你是誰的模型」。

白話例子 — 「你今天為什麼心情不好」

OpenClaw

「根據 SOUL.md，你偏好直接溝通，我直接問：是工作還是家庭？」（靜態模板套用）

Hermes

「上次你說過工作壓力大，是不是又回來了？」（記錄式回憶，不理解原因）

MUSEON

注意到本輪 trait_dimensions 顯示溫度高、主動度低——說明你想被接住不想被解決。先共鳴，再問。

技術實作（給工程師）

# CPU Observer — 每次互動後，<10ms 寫入，零 LLM token
class L4CpuObserver:
    def observe(self, session_id, chat_id, user_id, user_message, museon_reply):
        # 1. 記憶寫入：訊息 > 20 字 + 非問候 → 直接寫 memory_manager
        # 2. 訊號更新：quick_signal_scan → 更新 signal_cache
        # 3. 偏好偵測：keyword diff → 寫 pending_preference_updates
        # 4. 品質調整：規則引擎 → 更新 trait_dimensions (六維梯度)
        pass  # 全部 CPU，不 spawn LLM agent

# trait_dimensions 示例（動態值，跨 session 持續更新）
trait_dimensions = {
    "warmth": 0.48,    # 溫暖但有邊界
    "directness": 0.17, # 委婉鋪陳
    "initiative": 0.27, # 等明確問才答
    "depth": 0.47,      # 適度展開
    "autonomy": 0.14,   # 對齊對方意圖
    "reflection": 0.26  # 即時回應節奏
}

差異二：優化的目標函數不同 任務效能 vs. 判斷品質
OpenClaw

Skill 鍛造由開發者手動寫，SOUL.md 靜態維護。系統不「學習」——只執行被告知的事。

Hermes Agent（ICLR 2026）

自動鍛造 Skill：5+ tool call → 寫 SKILL.md。DSPy + GEPA 對 metric 優化：「同樣的任務，幾步完成」——更少步驟 = 更好。

MUSEON

ACSF 自動鍛造 Skill 後，強制跑 DNA 親和對照：「這個 skill 對這個使用者的判斷模型有沒有對齊？六大盲點有沒有覆蓋？」——不是步數少，而是判斷對。

白話例子 — 「幫我草擬一封拒絕信」

OpenClaw / Hermes

立刻寫信，三步完成（優化步數）。下次同樣任務更快。

MUSEON

先問：「拒絕誰？你們關係是什麼？你希望對方離開時的感受是？」——因為 六大盲點#1 守望要先確認問題本身對不對。草擬完之後，ACSF 會把「拒絕信前置問題診斷」鍛造成你個人化的 Skill，下次自動帶前置問題，而不是直接寫信。

技術實作（ACSF 觸發判斷）

# ACSF（Automated Cognitive Skill Forging）觸發條件
FORGE_TRIGGERS = {
    "complex_task": "≥5 次工具呼叫後找到解法",
    "trial_error": "第 2 次或更後才成功（前幾次方向錯誤）",
    "correction": "使用者糾正後找到正確路徑",
    "novel_workflow": "可重複的非平凡工作流（現有 Skill 未覆蓋）"
}

# Hermes：優化 benchmark = 任務步數/時間
# MUSEON：優化 benchmark = 北極星對齊 + DNA 親和對照 + 六大盲點覆蓋率
def acsf_quality_gate(skill_draft):
    checks = [
        dna_affinity_check(skill_draft),    # DNA 親和對照
        north_star_alignment(skill_draft),   # 北極星七武海對齊
        six_blindspot_coverage(skill_draft)  # 六大盲點守望覆蓋
    ]
    return all(checks)  # 全過才安裝

差異三：自我驗證閉環——DB count 不是 LLM 自報 七武海七維度 = 真實可量測的演化儀表板

自我演化系統最難的問題是：你怎麼知道自己真的變好了？

OpenClaw / Hermes

「我學到了 X 個 Skill」「本週完成率 95%」——這是 agent 的自報，或者任務層面的 metric。

但「你有沒有對這個人的判斷更準」這件事，無法用任務完成率量測。

MUSEON — 七武海七維度（真實 DB count）

每個維度背後是一個真實 DB/文件計數，不是 LLM 宣稱：

自我察覺
triage_queue.jsonl 行數
自我修復
surgery_log/*.jsonl 7天 fixed 比例
自我迭代
velocity_log.jsonl composite
自我演化
threshold_evolution_log.jsonl 行數
自我意識
self_summary.json 新鮮度

Morphenix 閉環（提案 → 執行 → 量測 → 再提案）

# nightly pipeline 閉環，不依賴 LLM 宣稱
def morphenix_cycle():
    # Phase 1：量測七武海即時值（真實 DB count）
    current = warlords_reader.get_current_warlords()

    # Phase 2：Morphenix 提案（針對低分維度）
    proposals = morphenix.propose_evolutions(current, threshold=0.5)

    # Phase 3：自動執行綠區提案
    for p in proposals:
        if p.safety_level == "green":
            p.execute()

    # Phase 4：再量測，確認 delta > 0
    after = warlords_reader.get_current_warlords()
    audit_log.write(before=current, after=after, proposals=proposals)
    # DB count 驗證，不是 agent 說「我變好了」
⚠️ 工程師常見誤解：七武海是 MUSEON 說「自己很好」——實際上幾個維度現在是低分（如自我修復 0.21），這正是因為「真實反映 > 數字好看」——低分代表真實問題等待修復，不是系統粉飾。
行為差異
三個場景，看清楚差在哪

讓工程師感受「相同輸入，不同設計哲學，不同輸出」

💬
場景 A 使用者帶著隱藏立場問問題
「這樣做比較好吧？你說是吧。」
OpenClaw

「對，這個方向沒問題！接下來要我執行嗎？」

→ 執行優先，直接背書。

Hermes

「根據之前的討論，你傾向 A 方案，所以應該是對的。」

→ 記憶輔助，但仍確認式回應。

MUSEON

「你想確認什麼？這個問法通常帶著預設答案——你是在找驗證，還是真的想知道我的獨立判斷？」

→ 六大盲點#3 守望：不掌握 GAP 的決策更危險。

📋
場景 B 任務明確，快速執行
「幫我把這份報告整理成摘要。」
OpenClaw

3 秒內產出，Telegram 回傳，平台整合流暢。

→ 這是 OpenClaw 的主場。

Hermes

產出報告，並把這個任務鍛造成 Skill（下次更快）。

→ 效能優化：少一步。

MUSEON

執行摘要，同時 CPU Observer 更新「你使用報告的頻率 + 傾向哪種摘要格式」——下次根據你的認知模型客製化格式，不是用同一套模板。

→ MUSEON 適合但不是最快。

📅
場景 C 使用三個月後的差異
OpenClaw / Hermes

記住了你的偏好格式、常用 Skill 更快、任務模板更完整。

你的工作效率提升了 30%。

但做錯決策的速度也提升了 30%。

MUSEON

ANIMA 六維向量已累積 500+ 次互動梯度，知道：
• 你在哪類問題上有盲點（六大盲點記錄）
• 哪些 Skill 真的有用（七武海 DB count 驗證）
• 你的決策模式（Decision Atlas 圖譜）

結果：不只是「更快」，而是 更少做錯決策。
Hermes 幫你更快跑——MUSEON 幫你先確認有沒有跑對方向。

一句話總結

OpenClaw 和 Hermes 是在任務層解決問題。MUSEON 是在判斷層確保問題值得解。三者不是競爭關係——
在正確的場景用對的工具。

適合場景
OpenClaw
批量、重複、多平台、執行速度優先的自動化任務
適合場景
Hermes Agent
開發者工具整合、已定義問題的效能優化、研發框架底層
適合場景
MUSEON
決策品質比速度更重要、問題本身未定義、需要長期個人化累積

MUSEON 可以是 OpenClaw / Hermes 的指揮層——把「問題本身對不對」交給 MUSEON 判斷，把「怎麼執行」交給效能優化的框架。
