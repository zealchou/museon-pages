Wan2.2 TI2V-5B：影像轉影片參數研究

2026-09-05・對象：1280×704、121 幀、24 fps、首幀 I2V、約 5 秒鏡頭

直接建議：下一次先固定 seed，將 sample_steps 從 8 提到 16，其餘採官方 TI2V-5B 配方：UniPC、shift 5.0、CFG 5.0。在「8 步約 9 分鐘、總時間不超過 20 分鐘」的保守線性估算下，16 步約 18 分鐘；它是最有證據、且不同時改動多個變數的改善法。不要先把 shift 或 solver 當作修臉旋鈕。

結論先講清楚：8 步對原生、未蒸餾的 TI2V-5B 是明顯偏低，不是官方品質設定的小幅縮減。官方 config 的 TI2V-5B 是 50 steps／shift 5.0／guidance 5.0／121 幀；官方程式也明說 steps 越高品質越好、但越慢。唯一能在本次時間上限內顯著增加的、且有直接因果依據的旋鈕是 steps。

可直接執行的組合

python generate.py \
  --task ti2v-5B \
  --size 1280*704 \
  --frame_num 121 \
  --ckpt_dir ./Wan2.2-TI2V-5B \
  --image ./input.png \
  --sample_steps 16 \
  --sample_shift 5.0 \
  --sample_guide_scale 5.0 \
  --sample_solver unipc \
  --base_seed 你的固定整數seed \
  --offload_model True \
  --convert_model_dtype \
  --t5_cpu \
  --prompt "..."

--convert_model_dtype 是官方 24 GB 單卡 TI2V 指令的一部分；它是把 DiT 轉為設定的參數 dtype，以便省記憶體，不是為了提升臉部品質。--offload_model True 與 --t5_cpu 也是記憶體／速度取捨，不是造成「動作弱、臉變形」的首要品質控制項。

逐題回答

1. 8 steps 是否太低？品質範圍是多少？

是，對 base TI2V-5B 而言太低。官方 TI2V-5B config 明定 50 steps；官方 pipeline 文件／程式也明定「higher values improve quality but slow generation」。所以 8 步是官方品質預設的 16%，不能期待它在 121 幀、720P、人物運動上有完整的去噪餘裕。

就「品質而非最快」而言，40–50 步是最合理的目標範圍：50 是直接官方配方；第三方的 MLX Wan 實作以同一 TI2V-5B 5B 單模型與 720P 配方，明寫 40 steps「recommended for best quality」。後者不是 Wan 官方 benchmark，故它只能支持「40 是可用的品質實務值」，不能取代官方 50。

但你的時限只允許折衷：16 steps 是時間受限的品質下限改善，不是品質最適值。若要追求真正的臉部穩定，40–50 步或改用有較強 I2V 能力／控制條件的模型，才是同一問題的另一個解法。

2. shift、guide scale 對動作與臉穩定度的方向？

參數官方能確認的含義可安全推論本次建議
sample_shiftnoise schedule shift；官方只寫「affects temporal dynamics」。TI2V-5B 的官方值 5.0。它改的是整段 flow-matching sigma/timestep 的分配；不是「動作幅度」的直接控制器。官方沒有給出「高一點必然更動／更穩臉」的單調關係。保持 5.0。不要為了動作直接改成 8；那是另一個 scheduler 實驗。
sample_guide_scaleclassifier-free guidance，官方定義為 prompt adherence vs. creativity；TI2V-5B 官方值 5.0。提高 CFG 會更強地服從正／負 prompt，可能令指定動作更被遵循；但它不保證動作更大，也不保證臉更穩。過度 guidance 在擴散模型通常會犧牲自然度／引入飽和或扭曲，因此不應無根據地往上推。保持 5.0。若 16 步同 seed 的臉仍明顯被 prompt 拉壞，才獨立試 4.5；這是診斷試驗，非已證實配方。

社群能找到的 TI2V-5B 具體配方只有低可信度的應用層例子：Draw Things 的「recommended settings」為 81 frames、CFG 4、UniPC Trailing、shift 8。它是不同 runtime／不同 scheduler 變體，且原討論正是在說 reference image 沒被充分使用，不能拿來直接覆寫官方 generate.py 的 5.0／5.0。另有 Wan2.2 I2V 使用者指出 shift 必須隨 steps、sampler、scheduler、model type 一起調，正好反駁「只改 shift 就能加大動作」這種說法；但那是 14B I2V 類推，不是 TI2V-5B 實驗。

3. UniPC 與 DPM++ 是否已知能解決「動作弱＋臉扭曲」？

沒有找到 TI2V-5B 的可信公開 A/B 證據，能宣稱 DPM++ 比 UniPC 更會保臉或更會做大動作。官方程式確實實作兩者：unipc 是預設，dpm++ 是另一個 flow-matching multistep scheduler；兩者都吃相同的 steps、shift 與 CFG。UniPC 原論文的優勢是以較少 function evaluations 達到高階求解精度，這支持它作為低步數的合理預設，卻不是 Wan 人臉 benchmark。

因此本案先選 UniPC：它是官方預設，且在 16 步這種仍遠低於原生 50 的預算下，換 solver 的證據不如多給去噪步數強。只有在 16-step UniPC 已跑過後，才用同 seed 做一次 16-step DPM++；若 DPM++ 對同一臉／動作主觀較好，再把它保留。不要用兩個不同 seed 的成片比較 solver。

4. 在不超過約 20 分鐘下，什麼組合同時最可能改善？

16 / 5.0 / 5.0 / unipc。它的邏輯是先把唯一明確品質瓶頸（8 steps）提高一倍，同時不偏離 TI2V-5B 的官方 temporal schedule 與 CFG。這很可能改善臉部的局部去噪與時間一致性；對「動作明顯度」的改善則是間接的——較完整的去噪會讓模型較有機會實現 prompt 已指定的動作，而非卡在保守的近靜止解。

動作幅度最該由 prompt 補上，而不是先賭 scheduler。把動作寫成單一、可觀察、連續的 5 秒事件，並指明起點、過程、終點與鏡頭。例如：

固定中景、鏡頭不移動。一名女子從靜止站立開始，
在 5 秒內清楚地把右手由腰側抬到肩高，手掌向鏡頭揮動兩次，
最後手停在肩高；臉始終朝向鏡頭，表情自然，頭部只有輕微轉動。

避免同時要求「走向鏡頭、快速轉頭、雙手跳舞、鏡頭環繞、景別切換」：對一張首幀和 5B 單模型而言，這是在同一段生成中同時施加多個 identity／肢體／鏡頭的高風險變量。先讓鏡頭固定、只做一個動作；需要快動作再明寫「正常速度／清楚可見的動作」，不要只寫「dynamic」。

5. 已知臉／身體變形問題的根本原因或限制？

有可觀察到的限制與社群回報，但沒有「低 steps 必然導致 temporal incoherence」的官方定理或 TI2V-5B 公認根因。應分成三層看：

  1. 低步數是本次最強的可修正風險。官方明定多 steps 會提升品質。8 步讓 121 幀的人臉、手、肢體在很少的反覆修正下收斂，合理地提高扭曲風險；但「必然」二字沒有來源支持。
  2. 模型／條件本身沒有身分鎖。官方 I2V 程式把輸入圖 resize、center-crop 後 VAE encode 成首幀 latent，並在每個 sampling step 把該條件混回 latent；它沒有 FaceID embedding、多張 reference，或姿態／動作控制輸入。這能錨住首幀，卻不能保證後續每一幀的人臉 identity。官方 repo 也已有使用者要求補回多 reference images 的 issue。
  3. TI2V-5B 是效率導向的高壓縮、5B dense 模型。官方模型卡寫明它使用 4×16×16 VAE 壓縮，連同 patchification 的總壓縮為 4×32×32；相較 Wan2.2 A14B 的雙專家 MoE，它不是同一個容量／架構。這是「它不應被期待在所有人物大動作上達到大型受控 I2V 的穩定度」的合理架構推論，不是官方宣稱的臉部缺陷原因。

社群現象與此一致但不能當成定量證明：官方 repo issue 有 TI2V animation 的 pixel jitter／flicker 回報，ComfyUI 討論也有人在預設 5B I2V workflow 見到 artifacts；另有 Wan2.2 I2V 使用者在臉一致性不足時採用後段 face swap。這些證據支持「臉漂移／時間 artifacts 是實務上會發生的已知限制」，不支持「某一個 solver 必定是根因」。

實驗順序：用最少生成次數得到可比較答案

  1. 選一張已裁成 1280×704 的清晰首幀；人物臉不要太小、不要大角度側臉、不要讓臉碰畫面邊緣。官方程式會先 resize 再 center-crop，不合比例的原圖可能在生成前就改變臉部構圖。
  2. 固定 prompt、negative prompt、image 與 --base_seed，跑 16 / 5 / 5 / UniPC。記錄總時間、臉部是否維持、動作是否完成。
  3. 若臉已改善、動作仍弱：不要先改 sampler；把 prompt 改為一個具起訖的動作，再跑相同參數。這是在測「指令是否不夠具體」。
  4. 若臉仍變形：先以同一 seed 試 CFG 4.5（只改一項）；若仍不行，再試 DPM++（回到 CFG 5.0，只改 solver）。每次都維持 16 steps。
  5. 若 16 步總時長低於 17 分鐘，且臉在第 16 步已明顯優於 8 步，才試 17 步。不要把一次很差的 seed 誤判為參數失敗；至少比較兩個固定 seed。
