Meta 開發者測試 App：接上 Instagram 留言／私訊 API 的實作步驟

查證日期：2026-09-27（Asia/Taipei）
適用目標：先讓「帳號本人管理的」Instagram 商業或創作者帳號，測試留言關鍵字回覆、留言私訊回覆與私訊自動回覆。
資料範圍：僅採 Meta for Developers 與 Meta 官方 Help Center；每個產品／介面名稱以本次讀到的官方頁面為準。

先講結論

現在的正式產品名稱是 Instagram API with Instagram Login；繁中開發者網站顯示為「含有 Instagram 登入的 Instagram API」。這條新流程不用把 Facebook 粉絲專頁連到 IG；不要誤選舊的 Instagram API with Facebook Login。官方說明這個新產品可處理留言、私訊與私密回覆，且服務帳號本人「擁有或管理」的 IG 專業帳號時可用 Standard Access（一般存取權限）。

因此，答案是：可以先測，不必等 App Review。 但不是「任何 IG 帳號都能測」。在 App 還在開發中時，測試者必須有此 App 的角色，並且在目標 IG 專業帳號上也有角色；目標帳號還必須是公開的專業帳號。若同一人建立 App 並管理自己的 IG，這些角色通常天然都在同一人身上；仍要在 API 設定頁把該 IG 加進 App，產生 token。

這不是三兩下就結束的流程，實際上有 9 個大階段：IG 轉專業帳號 → 登入／註冊開發者 → 建立商家型 App → 加入 Instagram 產品 → 加入自己的 IG 測試帳號與 token → 設 Webhook → 設 Instagram 商家登入 → 用留言／私訊做實測 → 需要服務其他商家時才送審。第 6、7 階段需要工具的開發者有一個可公開連線的 HTTPS 網址與後端程式；只有手機、沒有工具網站／伺服器時，能完成帳號與 App 設定，但還不能真正「自動」接收新留言／私訊。

先備好這些東西

要準備什麼 為什麼 需要額外驗證／付款嗎？
可登入的 Meta／Facebook 帳號 用來登入 developers.facebook.com、擁有 App 角色 官方建立 App 文件只寫須啟用 App Dashboard，沒有寫信用卡為本流程必要項。登入／註冊畫面若要求 email、手機簡訊或身分確認，照畫面完成；官方公開 Instagram 文件未列出固定的手機號碼或信用卡門檻。
自己的 IG 帳號與密碼 要加進 App、登入授權並產生 token 必須改成「專業帳號」（商業或創作者）且公開；不必是 Meta Verified 付費帳號。
一個有效聯絡 email 建立 App 時要填，Meta 用它通知 App 事項 不要求信用卡；官方建立 App 步驟要求此欄位。
工具的公開 HTTPS 網址（開發者準備） Webhook 的「回呼網址」、商家登入 OAuth redirect URI 都需要它 不是 Meta 的商業驗證，但不是純手機可完成的欄位。沒有它就無法即時自動接到留言／私訊。
第二個 IG 帳號（建議） 在目標 IG 貼文下真的留一則關鍵字留言，測「偵測留言 → 回覆」 不是 App Review 的門檻，只是最容易做出真實留言事件的方法。

不要把 access token、App Secret、Webhook verify token 截圖傳給別人或貼進聊天。 它們相當於工具的鑰匙。

階段 1：先在 IG App 把帳號改為公開的專業帳號

1.1 確認需要哪一種帳號

官方 Instagram API 頁面寫的是 Instagram professional account，並明確說支援 business（商業）與 creator（創作者）。本案兩者都可以；若是品牌／店家，選「商業」較直觀；個人內容創作者可選「創作者」。關鍵不是選哪一個，而是不要維持「個人帳號」，並要設為公開。

  • 在 IG App，右下角點自己的大頭貼進「個人檔案」。
  • 點右上角三條線（選單）。
  • 找「帳號類型和工具」／Account type and tools（不同版本有時顯示在「為專業人士」區塊）。
  • 點「切換為專業帳號」／Switch to professional account。
  • 選一個分類；接著選「商業」或「創作者」，依畫面完成設定。
  • 到「設定與動態」→「帳號隱私」確認「私人帳號」是關閉狀態，即帳號公開。

額外門檻： 官方 API 建立步驟明說加進 App 的 IG 帳號必須公開；沒有寫此切換需商業驗證、信用卡或手機號碼。帳號本身若因安全／地區情況被 IG 額外要求驗證，屬帳號畫面的即時要求，不能用本報告略過。

官方出處：

  • Instagram API with Instagram Login 總覽（支援商業與創作者；不需連 Facebook Page）
  • 建立 Meta App 以使用 Instagram API，第 7 步（新增帳號必須公開）
  • Meta 官方 Instagram Help Center：建立創作者帳號的 App 內路徑

最後一項是 Meta 官方 Instagram Help Center，且開發者文件本身連到此官方 Help Center 的「Instagram 專業帳號」說明；它是本清單中唯一不是 developers.facebook.com 的手機操作來源。

階段 2：登入 Meta for Developers，建立可管理 App 的開發者身分

  1. 在手機瀏覽器開 https://developers.facebook.com/，點 Log in。目前登入畫面可能出現「Log in with a managed Meta Account」等新字樣；它表示你可以用受管理 Meta 帳號登入，不表示要改走舊 Facebook Login API。
  2. 以擁有／管理目標 IG 的同一個 Meta 身分登入。第一次進入若出現「Register as a developer」或要求同意開發者條款，照頁面完成。
  3. 登入後進入 My Apps／「我的應用程式」。看不到建立按鈕時，先完成頁面要求的帳號驗證，然後重新開啟 App Dashboard。

額外門檻： 本次查到的 Instagram 建立 App、Getting Started、App Review、App Roles 官方頁面，沒有列「建立此測試 App 必須付信用卡」；也沒有把手機驗證列成 Instagram Standard Access 的前置條件。它們只要求 App 角色擁有 Meta developer account。由於帳號安全檢查會依帳號／地區動態顯示，若實際登入頁要求 email、手機 OTP 或 2FA，這是該帳號當下的必要畫面，應完成而非跳過。

官方出處： App Roles：管理員／開發人員需 Meta developer account、建立 Instagram App，第 1 步

階段 3：建立正確類型的 App（不要選到舊流程）

在 My Apps 畫面：

  1. 點右上角 Create app／「建立應用程式」。若已在某個 App 裡，要先點左上角 App 名稱下拉選單，再點 Create new app。
  2. 看到「Connect a business」／「連結商家」時，先知道這件事：要發佈 App 時官方要求 App 連到「已完成商家驗證」的商家；可以現在連，也可開發期間到左側 App settings > Basic 再連。純測自己的帳號、尚未發佈時，先繼續即可。
  3. 在「選擇使用案例」選 Other／「其他」，點 Next。
  4. 在「選擇 App type」選 Business／「商家」，點 Next。這一步是必要的：官方說只有商家類型 App 可以加入 Instagram 產品。
  5. 填 App name（只是 Dashboard 裡辨識用的名稱）與 Contact email，點 Next。進到新的 App Dashboard 即完成。

額外門檻：

  • 信用卡： 官方建立流程未列必填。
  • 商業驗證： 此刻可先略過；但官方明示「要發佈 App」前，必須連結已完成商家驗證的商家。
  • App 數量上限： 未連結已驗證商家的 App，若你已在 15 個 App 擔任管理員或開發者，可能不能再建；官方建議連結已驗證商家、移除不用的 App 或移除角色。

官方出處： 建立 Meta App，第 1–5 步與 15 個 App 限制

階段 4：把正確的 Instagram 產品加進 App

  1. 留在剛建立的 App Dashboard，向下滑到產品卡片。
  2. 找產品名稱 Instagram。官方對這張卡的描述是可讓創作者／商家管理訊息與留言、發布內容、查看洞察、標籤與提及。
  3. 點這張卡上的 Set up／「設定」。
  4. 系統會自動加入 Instagram API with Instagram Login（繁中：含有 Instagram 登入的 API）。這就是本案要用的產品。
  5. 不要因為看見 Facebook 就選「Instagram API with Facebook Login」。那是另一條流程，適用情境與權限名稱不同；本案依官方新流程用 Instagram Login，且不需要把 Facebook Page 接到 IG。

額外門檻： 官方產品加入步驟沒有列信用卡、手機驗證或商業驗證。若將來要服務「不屬於你／不由你管理」的多個商家，才會進入 Advanced Access + App Review／商業驗證的門檻（見階段 9）。

官方出處： 建立 Meta App，第 6 步、Instagram Login API 總覽

階段 5：把自己的 IG 專業帳號加為測試帳號，產生 token

這是「讓 App 知道它可操作哪個 IG」的關鍵步驟。

  1. 在 Dashboard 左側選 Instagram > API setup with Instagram login（繁中約為 Instagram > 含有 Instagram 登入的 API 設定）。
  2. 在「Generate access tokens」／產生權杖的區塊，點 Add Instagram account／「新增 Instagram 帳號」。
  3. 跳出 IG 登入頁時，登入階段 1 已設好的公開專業帳號；依同意畫面授權本 App 要求的權限。
  4. 回到 Dashboard 後，在該帳號旁點 Generate token／「產生權杖」，再登入一次 IG（若要求）。
  5. 複製 token，立刻交給工具的開發者安全儲存，不要貼到公開文件。Dashboard 產出的長效 token 官方寫為 60 天；之後需由程式重新整理／換發。
  6. 日後要新增或移除測試帳號，可走 App roles > Roles，或回到 Instagram > API setup with Instagram login。

額外門檻： 必須是公開專業帳號、必須能登入該 IG；官方沒有寫信用卡／商業驗證為這一步的必需條件。token 會過期不是帳號失敗；60 天到期前要由開發者依官方 refresh token 流程處理。

官方出處： 建立 Meta App，第 7 步、Getting Started：Dashboard 產生 token 的精確按鈕路徑及 60 天效期

階段 6：確認「開發模式測試」的角色條件

這一段回答「未過 App Review 可不可以今天測」。可以，但測試邊界是自己的／已授權管理的帳號，不是公開服務所有人。

  1. 若建立 App 的人就是目標 IG 的擁有人／管理者，先確認自己在 App 裡是 Admin 或 Developer。到左側 App roles > Roles 看得到即可。
  2. 若由不同的人測試，在同一頁的測試人員區塊，輸入對方的 Meta 帳號並送出 Tester 邀請；對方要接受邀請。
  3. 對方也必須在目標 IG 專業帳號有管理角色（不是只有會登入 IG 就夠）。官方的 Instagram Messaging 文件明定：測試人員必須「有 App 角色、授予 App 全部必要權限，並且在擁有 App 的 IG 專業帳號有角色」。
  4. 測試者用自己的 Meta／IG 登入，授與本案必要權限：instagram_business_basic、instagram_business_manage_comments、instagram_business_manage_messages。舊的 business_manage_* scope 已停用，別把舊教學複製進工具。

能測到的範圍： App Roles 官方文件寫明，測試人員在 App「處於調整中」（開發模式）可授與 App 任意權限、使用所有功能；Instagram API 文件則把「本人擁有／管理，且在 App 管理員中加入的 IG 專業帳號」列為 Standard Access。這足以測本案自己的留言、私訊和 Webhook。不能據此宣稱可讓任意外部客戶連進來使用；那是 Advanced Access／App Review 的範圍。

額外門檻： 不需 App Review；官方亦未列信用卡。一般未連結 App 最多 50 名 testers；連結且已驗證商家資產管理組合的 App，管理者加測試者合計上限為 500。

官方出處： App Roles：測試者在開發中可使用所有功能、邀請與人數限制、Instagram Messaging：測試者的雙重角色要求與 Standard/Advanced Access、App Review：只服務本人管理商家時 Standard Access、不需要審查

階段 7：讓工具收到新留言／私訊（Webhook；需要開發者）

自動回覆不能靠人手重整 API；工具需要一個伺服器接收 Meta 推來的新事件。

  1. 請開發者先準備一個可從網際網路存取的 HTTPS callback URL，和一段自訂的 Verify token 文字。這兩個不是 IG 密碼。
  2. Dashboard 左側 Instagram > API setup with Instagram login，到 Webhooks 區塊點 Configure／「設定」。
  3. 在彈窗填 Callback URL（開發者提供的 HTTPS 網址）與 Verify token，按 Save。
  4. 點 Manage／「管理」，確認要接的事件有訂閱。留言關鍵字至少要 comments（直播才另加 live_comments）；私訊至少要 messages，並依工具需要加 messaging_optins、messaging_postbacks、messaging_reactions、messaging_referrals、messaging_seen。
  5. 讓開發者做一次真實事件測試：有人在貼文留言／傳私訊後，伺服器是否收到 Webhook，再由工具依 keyword 判斷與回覆。

額外門檻： 官方要求 callback URL 和 verify token，但本設定步驟未列商業驗證、信用卡或手機號碼。真正的門檻是「要有可公開連到的 HTTPS 後端」；沒有後端不可能做到即時自動化。

官方出處： 建立 Meta App，第 8 步（Webhook 的按鈕、欄位及預設事件）、留言審核：comments／live_comments Webhook 與回覆流程、傳訊 API：所需 Webhook events

階段 8：設定「Instagram 商家登入」（正式讓帳號授權工具；需要開發者）

Dashboard 產 token 足夠測自己的帳號；但工具若有「連接我的 IG」按鈕，則要完成 OAuth／商家登入設定。

  1. 在同一個 Instagram > API setup with Instagram login 頁面，到第 3 段 Set up Instagram business login／「設定 Instagram 商家登入」。
  2. 點 Configure／「設定」，在彈窗填開發者提供的 Redirect URL，按 Save。
  3. 複製畫面顯示的 Embed URL；開發者把它放到工具網站或 App 的「連接 Instagram」按鈕上。
  4. 點 Business login settings，補齊必要設定：允許的 OAuth redirect URI、Deauthorize callback URL（使用者解除授權時通知工具的網址）、Data deletion request URL（資料刪除請求網址），按 Save。
  5. 用自己的 IG 點工具的連接按鈕，完成 Instagram 登入與同意；開發者用返回的授權碼交換 token。新版 scope 用 instagram_business_basic、instagram_business_manage_comments、instagram_business_manage_messages（若要發文才加 content publishing）。

額外門檻： 此步官方沒有列信用卡、手機號碼或商業驗證；但每個 URL 必須真實存在、能由開發者控制。授權碼只可用一次且有效 1 小時；短期 token 可換為 60 天長效 token。

官方出處： 建立 Meta App，第 9 步、Instagram 商家登入：scope、redirect URI、token 交換規則

階段 9：今天就做的兩種真實測試

A. 留言關鍵字 → 公開留言回覆或私訊回覆

  1. 用目標 IG 專業帳號發一篇公開貼文／Reel。
  2. 用第二個 IG 帳號在那篇貼文底下留言，例如「我要關鍵字」。
  3. Webhook 收到 comments 事件後，工具比對文字；若符合，就可：
    • 對該留言做公開回覆：POST /<IG_COMMENT_ID>/replies，需要 instagram_business_basic + instagram_business_manage_comments。
    • 或做「留言後私訊」：以留言 ID 呼叫 POST /<APP_USERS_IG_ID>/messages，recipient 填 comment_id。這正是官方的 Private Replies 流程；可在留言後 7 天內發一則私訊。若對方再回覆，才可在其回覆後 24 小時內追發。
  4. 留言者確認有收到公開回覆，或在 IG 收件匣／要求資料夾收到私訊；這就是成功證據。

重要限制： 留言私訊回覆不是無限制廣播；官方限制每位留言者只能收到一則，且需在 7 天內。它靠的是 comments Webhook 與留言管理權限，不是先要求對方傳 DM。

官方出處： 留言審核：讀取 Webhook、回覆留言、Private Replies：留言 → Webhook → 私訊的完整流程與 7 天／一則限制

B. 私訊關鍵字 → 私訊自動回覆

  1. 最貼近真實情境：用第二個 IG 帳號先對目標專業帳號傳一則 DM，例如「我要資料」。
  2. Webhook 收到 messages 後，工具依 keyword 呼叫 /<IG_ID>/messages 回覆。
  3. 官方規則是：對方必須先傳訊息給專業帳號，工具才可主動回；對方傳訊息後有 24 小時可自動回覆。
  4. 若只有一個 IG 專業帳號，官方另提供 Self Messaging 測試：同一專業帳號可同時扮演商家與 IG 使用者，測預覽／自動化，不必兩個帳號；仍需此帳號已連到 App、訊息權限與 Webhook 已設好。

官方出處： 傳訊 API：先由使用者開啟對話與 24 小時窗口、Self Messaging：單一 IG 專業帳號測私訊

什麼時候才需要 App Review／商業驗證？

情況 App Review 商業驗證 今天的自測是否受影響？
只服務自己擁有或管理、且已加到 App 的 IG 專業帳號 不需要（Standard Access） 官方建立流程只說「發佈 App」前需連結已驗證商家；本地／開發中自測不是此門檻 不受影響，可先測。
工具要讓其他不由你管理的商家／創作者登入使用 需要 Advanced Access 與 App Review Meta 權限文件說所有要求 Advanced Access 的 App 都要商業驗證 不能拿自己的 tester 身分取代審查。
要正式發佈 App 建立 App 頁說要準備 App Review（視權限／用途） 必須連結已完成商家驗證的商家 與「只測自己的帳號」是不同關卡。

送審時，官方要求外部可載入及測試的 App、逐步使用案例、每個權限的端到端螢幕錄影、隱私政策 URL、App icon、App category、商業 email，以及供審查者測試的登入／測試指示。這些是將來服務外部客戶才要準備的，不是今天生成測試 token 的前提。

官方出處： Instagram API App Review（開發情境表及送審步驟）、Permissions（Advanced Access 需商業驗證）

本次逐頁檢查的 Instagram API 官方設定頁為文字步驟，沒有提供可獨立開啟的「逐格截圖教學」或「官方設定影片」連結；因此沒有自行補造截圖或引用第三方影片。可直接照下列官方、含實際按鈕文字的資源操作：

  • Getting Started（Dashboard 產 token）
  • Instagram 商家登入（連接按鈕／OAuth 設定）

「官方沒有明講」的查核紀錄

為避免把「我沒看到」誤寫成「Meta 絕對不要求」，下列否定結論都有範圍。

問題 結論的精確說法 查過的官方頁面與關鍵詞
建立此自測 App 是否一定要信用卡？ 在本次查閱的 Instagram 建立／登入／測試／審查官方頁中，未列信用卡為建立 App、加入自己的 IG、產 token 或 Standard Access 測試的必填項。不等於某個 Meta 帳號的安全頁永遠不會要求付款方式。 建立 Instagram App、Getting Started、Business Login、App Roles、App Review、Permissions；搜尋／頁內核對：credit card、payment、phone、verification、Standard Access。
建立測試是否一定要完成商業驗證？ 不需要 App Review 的自有／自管帳號 Standard Access 與「Advanced Access 必須商業驗證」是兩件事。建立頁另說「發佈 App」前要連結已驗證商家。 建立 Instagram App、App Review、Permissions；關鍵詞：business verification、publish、Standard Access、Advanced Access。
是否有官方逐步影片／截圖 URL？ 本次列出的五個核心頁面都沒有看到可獨立開啟的設定影片或逐格截圖教學連結；所以只列其文字步驟頁，不用第三方影片補數。 建立 Instagram App、Getting Started、Business Login、App Roles、App Review；關鍵詞：video、screenshot、tutorial、image。

最短可執行清單（交給使用者／開發者）

  1. 使用者：把 IG 改成「公開＋商業／創作者」。
  2. 使用者：到 developers.facebook.com → Create app → Other → Business → 填 App name／email。
  3. 使用者：在產品卡點 Instagram 的 Set up；確認是 Instagram API with Instagram Login。
  4. 使用者：Instagram > API setup with Instagram login → Add Instagram account → 登入自己的 IG → Generate token；安全交給開發者。
  5. 開發者：設好 Webhook callback／verify token，訂閱 comments 和 messages。
  6. 開發者：設好 Business Login 的 redirect URI、deauthorize 與 data deletion URLs。
  7. 使用者＋開發者：第二個 IG 留關鍵字、傳 DM；確認 webhook 收到、工具回覆成功。
  8. 先不要急著送 App Review；只有工具要接外部客戶時，再做 Advanced Access、商業驗證與審查。
