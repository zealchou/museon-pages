01 — 專案背景與挑戰

專案概述

本專案的目標是為傳統市場攤商（年齡層 65-75 歲以上）建構一套批發/供應鏈下單系統。這些使用者每天凌晨 3-5 點向供應商叫貨，長年以「電話、手寫單、LINE 文字訊息」完成。系統化的目的不是取代他們的習慣，而是讓習慣數位化的阻力降到最低。

四大核心挑戰

1
視覺退化（Vision Decline）

老花眼（presbyopia）導致近距離閱讀困難，對比敏感度下降，色覺偏移（藍-綠辨別力下降）。在傳統市場光線不均的環境下，螢幕可讀性更是嚴峻。

2
精細運動能力變化（Motor Skill Changes）

手指靈活度降低、輕微顫抖（tremor）導致點擊偏移、反應時間變長。在濕手（處理生鮮食材）或低溫環境下操作手機更加困難。

3
科技不熟悉（Tech Unfamiliarity）

多數目標使用者僅會使用 LINE 傳訊息、打電話、看 YouTube，對「APP 安裝、帳號註冊、密碼管理」等概念陌生。任何需要學習的新操作都是流失風險。

4
信任門檻（Trust Barrier）

高齡者對數位系統的信任建立時間長——「我按了之後東西真的會送來嗎？」「價格有沒有被改？」「我的資料會不會被偷？」每一個疑慮都需要在 UI 上給出明確、即時的答案。

設計核心原則：這不是一個「功能多就是好」的系統。每多一個按鈕，就多一個讓老闆放棄的理由。能減則減，能大則大，能熟悉則熟悉。

02 — 高齡者使用者特徵分析

視覺系統（65-75+ 歲）

  • 老花眼（Presbyopia）：水晶體硬化，近距離聚焦困難。40 cm 以內的小字幾乎無法辨識。手機通常持在 35-45 cm 距離觀看。
  • 對比敏感度下降：淺灰色文字在白色背景上幾乎「消失」。需要至少 7:1 的對比度（WCAG AAA 等級）才能舒適閱讀。
  • 色覺偏移：藍-綠-紫色域的辨別力下降。紅色與黃色的辨識相對穩定。切勿僅用顏色傳達資訊（例如紅=錯誤），必須輔以圖示或文字。
  • 暗適應變慢：從亮處進入暗處（或反之），眼睛需要更長時間適應。避免介面中出現大面積深色/亮色的突然切換。
  • 眩光敏感：純白背景 (#FFFFFF) 在某些光線下造成不適。使用暖調背景如 #F7F5F0。

運動系統

  • Fitts' Law 放大效應：觸控目標越小、距離越遠，高齡者的點擊錯誤率呈指數上升。標準 44px 按鈕對年輕人夠用，對高齡者不夠——需要 56-64px。
  • 手指顫抖：靜止性顫抖導致觸控容易偏移 5-10px。按鈕間距需 ≥12px 以防誤觸。
  • 握力變化：長時間單手持機困難。介面的核心操作區應集中在螢幕中央偏下（拇指自然觸及區）。
  • 反應時間：65+ 歲的平均反應時間比 25 歲慢 50-100%。任何有時間限制的操作（倒數計時、自動登出）都是地雷。

認知系統

  • 工作記憶容量下降：同時處理的資訊量從 7±2 降到 4±1。每個畫面不應超過 3-4 個需要決策的項目。
  • 資訊處理速度變慢：需要更多時間閱讀、理解、做決定。不要用動畫或自動輪播搶走他們的閱讀時間。
  • 程序性記憶穩健：「一旦學會，就不會忘」。如果操作流程固定且簡單，高齡者反而比年輕人更穩定執行。
  • 經驗與智慧：這些市場老闆做生意做了 30-50 年，對「叫貨」的流程比任何人都熟。系統應該映射他們既有的心智模型，而不是強迫他們學新的。

科技使用行為

  • 會用的：LINE（傳文字、語音訊息、看照片）、打電話、YouTube、相機
  • 勉強會用的：LINE Pay、全聯 PX Pay（因為子女幫忙設定）
  • 不會用的：Email、App Store 搜尋安裝、帳號密碼管理、通知設定
  • 恐懼的：「亂按會不會扣錢」「資料會不會外洩」「手機會不會壞掉」

關鍵量化指標

項目 一般標準 高齡者建議值 說明
最小觸控目標 44 × 44 px 56 × 56 px（建議 64px） Apple HIG 44px 是最低標，手指顫抖需更大容錯
觸控目標間距 8px ≥ 12px 防止顫抖造成的誤觸鄰近按鈕
最小內文字型 14-16px 18px（建議 20-24px） 老花眼 + 35-45cm 持機距離

03 — 核心設計原則

以下八條原則從高齡者特徵研究直接推導，每條附帶具體數值與實作方式。

1
超大觸控目標

原則：所有可點擊元素最小 56px，建議 64px。按鈕間距 ≥ 12px。

原因：Fitts' Law + 手指顫抖。小目標的點擊錯誤率在 70+ 歲群體高達 23%（vs. 年輕人 4%）。每次誤觸都是一次挫折，三次挫折就會放棄。

實作：

  • 主要 CTA 按鈕：高度 64px，寬度至少佔螢幕 80%
  • 數量 +/- 按鈕：56px 圓形，間距 16px
  • 列表項目：整行可點擊（row height ≥ 64px）
  • 底部導航列圖示：48px icon + 16px 文字標籤
2
高對比文字

原則：文字對比度 ≥ 7:1（WCAG AAA）。最小字型 18px，建議 20-24px。

原因：65+ 歲的對比敏感度僅為年輕人的 60-70%。WCAG AA（4.5:1）是「年輕人可讀」的標準，不是「老花眼可讀」的標準。

實作：

  • 主文字 #12121A on #F7F5F0（對比 14.8:1）
  • 次要文字用 #5A5A6E（對比 7.2:1），不可再淺
  • 禁止淺灰色 placeholder 作為唯一提示——必須有標籤
  • 禁止彩色背景上的白色小字（如淺藍底白字）
3
減法導航

原則：每個畫面最多 3-4 個選項。不使用巢狀選單。流程必須線性。

原因：工作記憶 4±1 + 決策疲勞。每多一個選項，決策時間指數增長（Hick's Law）。傳統市場老闆的決策模式是「每天叫差不多的貨」，系統應該反映這個現實。

實作：

  • 首頁只有：常用供應商（6 格）+ 歷史訂單 + 設定，三個概念
  • 不使用漢堡選單或 Tab Bar 超過 4 個 Tab
  • 每個畫面一個主要動作（Primary CTA）
  • 「返回」永遠在固定位置（左上角），且觸控區域放大到 56px
4
熟悉的隱喻

原則：用現實世界的概念設計 UI。模仿紙本叫貨單、計算機、收據。

原因：高齡者的長期記憶和程序性記憶穩健。他們用了幾十年的紙本叫貨流程是最好的設計參考。「讓 APP 看起來像他們已經會用的東西」。

實作：

  • 下單頁面的排版模仿手寫叫貨單：品名 | 數量 | 單位
  • 數量輸入用大大的 +/- 按鈕，像計算機
  • 確認頁模仿收據格式，有虛線分隔、總數統計
  • 「打勾 = 完成」「紅色 = 注意」「綠色 = 安全」這些通用隱喻
5
容錯設計

原則：任何操作都可以撤銷。破壞性操作前必須確認。不設計有時間限制的操作。

原因：「按錯了怎麼辦？」是高齡者最大的恐懼。如果一次誤操作導致「不可挽回的後果」，他們會永遠不敢再用。

實作：

  • 送出訂單後有 60 秒的「取消」視窗（大按鈕，不是小小的連結）
  • 刪除操作需兩步確認：「確定要刪除？」→「是，刪除」
  • 永遠不自動登出（或至少 24 小時以上）
  • 沒有任何倒數計時的操作
  • 誤觸返回鍵不會丟失已填的資料
6
一致性

原則：同樣的動作永遠在同樣的位置。同樣的顏色永遠代表同樣的意思。

原因：程序性記憶的建立需要重複。一旦「送出在右下角」，就永遠在右下角。一次例外就破壞整個學習。

實作：

  • 所有頁面的主要 CTA 都在底部固定區（fixed bottom bar）
  • 「返回」永遠在左上角
  • 橙色/紅色 = 主要動作，灰色 = 次要/取消
  • 頁面標題永遠在頂部中央，字型大小一致
7
漸進式揭露

原則：只顯示當下需要的資訊。進階功能隱藏在「更多」後面。

原因：資訊過載是高齡者放棄使用的第一原因。「看不懂的東西太多了」=「這個太複雜我不會用」。

實作：

  • 首次使用只開放核心功能（叫貨 + 看歷史）
  • 統計報表、進階設定等放在子頁面，首頁不顯示入口
  • 商品列表優先顯示「常用品項」，完整品項需要主動展開
  • 新功能不用彈窗介紹，用溫和的提示點（紅點）
8
即時回饋

原則：每個操作都有大幅度的視覺 + 觸覺 + 可選聽覺回饋。

原因：高齡者的反應時間慢，如果按下按鈕後 0.5 秒沒反應，他們會以為「沒按到」而重複點擊，造成雙重送出或跳頁混亂。

實作：

  • 按鈕按下瞬間：顏色明顯變化（深 30%）+ 輕微縮小（scale 0.96）
  • 加入數量：數字彈跳動畫 + 手機震動（haptic feedback）
  • 送出訂單：全螢幕綠色打勾 + 「訂單已送出」大字 + 震動
  • 載入等待：使用骨架屏（skeleton），不要空白頁面
  • 可選：按鈕按下音效（咔噠聲），由使用者自行開關

色彩使用建議：
  • 主要動作（送出、確認）：暖橙色（如 #C4502A），白色文字
  • 成功狀態（訂單完成、已送達）：綠色（#2D8A6E）
  • 警告/注意（缺貨、價格變動）：金黃色（#C9943A）+ 圖示
  • 錯誤/取消：紅色（#C4402A）+ 文字說明，不可只靠顏色
  • 背景：暖白（#F7F5F0 or #FAF8F5），不用純白
  • 禁止：藍色連結（高齡者常不知道藍色底線字可以按）

05 — 參考 APP 與案例分析

以下分析 8 款在「簡易操作」或「高齡友善」方面有參考價值的 APP，萃取可學習的設計模式。

LINE 台灣首選
值得學習
  • 底部 Tab Bar 固定 4 個圖示 + 文字標籤，不隱藏
  • 大頭貼 + 名字的辨識方式（人臉比文字好記）
  • 語音訊息一鍵錄製，降低打字門檻
  • 「已讀」回饋建立信任：「對方看到了」
需要避免
  • 設定頁巢狀層級太深，高齡者常迷路
  • 廣告跳窗干擾，增加誤觸風險
健保快易通 政府 APP
值得學習
  • 首頁大圖示 + 大文字網格排列（2×3 或 3×3）
  • 有專門的「大字版」模式可切換
  • 口罩預購流程：線性步驟、一頁一任務
需要避免
  • 功能太多但沒有個人化推薦，首頁選項過載
  • 驗證機制（健保卡 + 手機）對高齡者太複雜
拼多多（長輩模式） 最佳實踐
值得學習
  • 字型整體放大 30-40%，間距加倍
  • 「常買清單」自動根據歷史推薦
  • 一鍵再買（重複訂單）功能突出
  • 精簡導航，只保留「首頁、訂單、我的」三個 Tab
需要避免
  • 拼團/分享裂變機制增加認知負擔
  • 紅包彈窗引導誤觸
抖音/TikTok（適老模式） 中國經驗
值得學習
  • 系統級「適老模式」：字型 + 按鈕 + 對比度一鍵切換
  • 極簡核心互動——上滑就是下一個，沒有其他需要學的
  • 大播放按鈕、大暫停區域
需要避免
  • 手勢操作（滑動）不適合精細運動退化的高齡者
  • 無限滾動沒有明確「邊界」感
Uber Eats / foodpanda 外送參考
值得學習
  • 商品卡片：大圖 + 品名 + 價格，三個資訊一目瞭然
  • 數量選擇器 +/- 按鈕清晰
  • 購物車浮動在底部，隨時可見總額
  • 訂單進度追蹤的即時回饋
需要避免
  • 商品選項過多（大小、辣度、配料）增加決策負擔
  • 促銷資訊太多、排版混亂
  • 註冊流程需要 Email + 信用卡
7-ELEVEN ibon Kiosk 設計
值得學習
  • 大面積按鈕佈局，每頁 4-6 個選項
  • 明確的步驟指示：「Step 1 → 2 → 3」
  • 完成後列印收據——實體憑證建立信任
需要避免
  • 觸控不夠靈敏，高齡者常「按了沒反應」
  • 操作有超時限制（60 秒自動返回首頁）
全聯 PX Pay 台灣超市
值得學習
  • 首頁核心功能突出：付款碼佔半個螢幕
  • 會員點數顯示直觀
  • 操作極簡：掃碼 → 付款 → 完成
需要避免
  • 促銷 Banner 輪播搶走注意力
  • 福利卡綁定流程需要太多資訊輸入
  • 字型偏小，子頁面資訊密度過高
日本 Mercari（メルカリ） 極簡電商
值得學習
  • 介面極度乾淨，留白充足，視覺層次分明
  • 圖片優先——商品頁以大圖為主，文字為輔
  • 操作用引導式步驟（wizard pattern），一步一步走
  • 「傻瓜相機」式刊登流程：拍照 → 自動辨識 → 確認
需要避免
  • 日本市場的 UI 慣例與台灣不同，需本地化
綜合啟示：最成功的高齡友善設計有三個共同點——(1) 首頁只做一件事 (2) 核心流程不超過 3 步 (3) 有「重複上次」的快捷方式。拼多多的長輩模式和 Mercari 的極簡風格是最值得深入參考的兩個案例。

08 — 常見地雷與解決方案

以下整理高齡者 UX 設計中最常見的錯誤，每個都附帶失敗原因和具體解法。

地雷 為什麼會失敗 解決方案
文字太小 老花眼在 35-45cm 距離無法閱讀 14px 以下文字，使用者會湊近螢幕、瞇眼、或直接放棄。 最小 18px，建議 20-24px。支援系統字型縮放。永遠允許放大。
選項過多 工作記憶 4±1 + Hick's Law。一頁 10 個按鈕 = 高齡者看到的是「一片混亂」。 每頁最多 3-4 個核心選項。次要功能收到「更多」裡。優先顯示「常用」。
純手勢操作
（左滑刪除、下拉刷新）		 手勢是隱藏指令，沒有視覺提示。高齡者根本不知道可以「滑」。手指顫抖也讓精確滑動困難。 所有操作必須有按鈕替代方案。手勢只是「快捷鍵」，不是唯一路徑。
超時自動登出 高齡者操作速度慢，5 分鐘填不完一張單。被登出後找不回進度 = 暴怒或放棄。 至少 24 小時不登出。離線狀態下保留草稿。重新登入只需手機 OTP。
CAPTCHA 驗證碼 圖形辨識困難（色覺退化 + 對比度低）。滑動驗證需要精確操控。耗時 > 30 秒 = 放棄。 用手機 OTP 簡訊取代。裝置信任機制：同一支手機免驗證。
複雜密碼要求 「需包含大小寫、數字、特殊符號」對日常只用注音的高齡者是天書。忘記密碼後無法自行重設。 免密碼登入：手機號碼 + OTP。或用 4-6 位數字 PIN 碼。生物辨識（指紋/Face ID）作為備選。
漢堡選單
（三條線圖示）		 研究顯示 65+ 歲使用者有 60% 不認得漢堡選單圖示。「三條線代表選單」不是直覺。 用固定底部 Tab Bar（最多 4 個 Tab），每個 Tab 有圖示 + 文字標籤。
彈出式對話框
（Modal / Pop-up）		 突然出現的東西打斷心流、造成恐慌（「這是什麼？是不是中毒了？」）。按「X」關閉的觸控區太小。 改用整頁轉場或底部滑出面板（bottom sheet）。必須用時，「關閉」按鈕 ≥ 56px，位於右上角或底部。
僅靠顏色區分 藍-綠色盲在 65+ 歲男性中比例高。「紅色 = 錯誤」如果沒有圖示或文字輔助，色覺退化的使用者看不出差異。 顏色 + 圖示 + 文字三重標記。如：紅色背景 + × 圖示 + 「訂單取消」文字。
自動輪播 / Carousel 自動切換的內容搶走閱讀時間。高齡者還沒看完第一張，就被切走了，造成焦慮和不信任。 靜態內容。如果需要多項展示，用上下滾動列表或分頁標籤（非自動切換）。
雙欄/多欄排版 視線在欄位間跳動增加認知負擔。手機螢幕上的雙欄文字太小。 全部單欄排版。一行一個資訊。上下滾動比左右移動直覺。
英文介面/術語 「Submit」「Cancel」「OK」「Error 404」——不是每個 65 歲的台灣人都看得懂英文。 100% 繁體中文介面。「送出」「取消」「確定」「出了點問題，請再試一次」。

09 — 開發實作建議

技術架構建議

1
PWA 優先（Progressive Web App）

為什麼：傳統市場老闆不會自己去 App Store 搜尋安裝。PWA 可以由子女或業務人員透過一個連結「加到主畫面」，看起來像原生 APP，但不需要 Apple/Google 帳號。更新也不需要使用者手動操作。

注意：iOS 上 PWA 的推播通知支援有限（iOS 16.4+），需考慮 LINE Notify 或 SMS 作為通知備案。

2
離線優先（Offline-First）

為什麼：傳統市場環境的網路訊號不穩定（地下室、鐵皮屋、人潮密集區）。凌晨 3-5 點叫貨時如果「讀取中...」轉 10 秒，老闆直接打電話了。

實作：

  • Service Worker 快取供應商清單和品項資料
  • 訂單先存在本地 IndexedDB，有網路時自動同步
  • 離線狀態下顯示明確提示：「目前離線，訂單會在連上網路後自動送出」
  • 同步成功後推送確認通知
3
系統無障礙 API 整合

為什麼：如果使用者已經在手機系統層級開啟了「大字體」或「高對比」，APP 應該自動跟隨，而不是忽略。

實作：

  • CSS：font-size 使用 rem 不用 px（配合系統字型縮放）
  • iOS：尊重 Dynamic Type 設定
  • Android：尊重系統顯示大小設定
  • prefers-contrast: high 媒體查詢，偵測高對比模式
  • prefers-reduced-motion 偵測減少動態效果偏好
  • 所有互動元素加 aria-label（為未來 VoiceOver / TalkBack 支援做準備）
4
語音輸入支援

為什麼：打字對高齡者是痛苦的——注音輸入法需要精確選字、手寫辨識需要精細運動控制。但他們很會「講話」。LINE 語音訊息是他們最常用的功能。

實作：

  • 搜尋供應商/品項時，提供麥克風按鈕
  • 使用 Web Speech API 或原生語音辨識
  • 支援台語/國語混用的語音輸入（考慮 Whisper API 作為後端）
  • 語音備註功能：錄下「明天多送兩箱」，附在訂單上
5
真實使用者測試

為什麼：沒有任何設計規範可以取代「看著 70 歲的人操作你的 APP」的洞察。你會看到你完全意想不到的行為——用食指「戳」螢幕、不知道可以滾動、把所有東西都當成按鈕按。

測試建議：

  • 至少找 5 位 65+ 歲的傳統市場攤商做原型測試
  • 先用紙本原型（paper prototype）測試流程邏輯
  • 觀察他們拿手機的方式（單手/雙手）、眼睛到螢幕的距離
  • 記錄每次猶豫和誤操作——這些是最寶貴的設計線索
  • 測試環境要在市場現場，不是辦公室（光線、噪音、濕手都是變數）
  • 每次測試改善後再測，至少迭代 3 輪
6
數據監測與持續優化

上線後必須追蹤的指標：

  • 任務完成率：「開始下單 → 成功送出」的轉換率（目標 > 90%）
  • 平均操作時間：完成一次下單的時間（目標 < 60 秒）
  • 誤觸率：「返回」「取消」「重新輸入」的頻率
  • 跳出點：使用者在哪個步驟放棄最多
  • 重複下單使用率：「再叫一次」功能的使用比例（目標 > 60%）
  • 客服求助率：多少使用者需要打電話問「怎麼用」

技術選型建議

面向 建議方案 原因
前端框架 React / Vue + PWA 成熟的 PWA 生態系，離線支援完善
UI 組件庫 自建（Design Token 驅動） 現有組件庫的預設值都太小，自建才能確保高齡友善
狀態管理 本地快取 + API 同步 離線優先架構
登入機制 手機號碼 + OTP 零密碼，裝置信任後免登入
通知 LINE Notify + SMS 備案 高齡者最常看 LINE，推播通知可能被忽略
語音辨識 Web Speech API / Whisper 支援國台語，降低打字需求
後端 Node.js / Python + REST API 快速開發，容易維護
資料庫 PostgreSQL + Redis 訂單資料 + 快取

10 — 下一步行動清單

以下是建議 Feng 團隊依序執行的行動項目，每項附帶預估時間和交付物。

Phase 1：使用者研究（1-2 週）

  • 田野調查：拜訪 3-5 個傳統市場攤位，觀察他們目前的叫貨流程（電話/LINE/手寫單）。拍照記錄（經同意）。
    交付物：使用者旅程地圖（Current State Journey Map）
  • 裝置調查：記錄目標使用者實際使用的手機型號、螢幕尺寸、作業系統版本。
    交付物：裝置清單 + 最低規格基準（e.g., iPhone 8 / Android 10）
  • 痛點訪談：用口語化的方式問：「你最怕手機的什麼？」「你用 LINE 的時候最困擾的是？」「如果可以按一個按鈕就叫好貨，你會想用嗎？」
    交付物：5 份訪談摘要 + 痛點排序

Phase 2：原型設計（1-2 週）

  • 紙本原型：根據本報告的 Wireframe 建議，畫出紙本版的四個畫面。帶到市場給攤商操作。
    交付物：紙本原型 + 3 份使用者測試紀錄
  • 數位原型：用 Figma 製作可互動原型，在真實手機上測試。重點驗證：觸控目標大小是否足夠、文字是否可讀、流程是否直覺。
    交付物：Figma 互動原型 + 可用性測試報告
  • 無障礙審計：用 Lighthouse / axe 等工具檢查對比度、觸控目標、ARIA 標籤。
    交付物：無障礙審計清單（Accessibility Audit Checklist）

Phase 3：開發與測試（4-6 週）

  • Design Token 系統建立：將本報告第 4 章的規範轉化為 CSS Variables / Design Tokens，確保全系統一致性。
  • 核心功能開發：MVP 只做三件事——(1) 選供應商 (2) 下單 (3) 重複上次訂單。其他功能全部 Phase 2。
  • 真實環境測試：在市場現場、凌晨時段、用目標使用者的手機測試。至少 3 輪迭代。
  • 競品研究：調查台灣現有的市場批發數位化系統（如：批發市場交易系統、LINE 機器人叫貨群組），了解已有的解決方案和不足之處。

Phase 4：上線與優化（持續）

  • 軟啟動：先找 5-10 個友好攤商使用，收集回饋。不要一次大規模推廣。
  • 數據監測：部署本報告第 9 章建議的監測指標，每週檢視。
  • 持續迭代：根據使用數據和使用者回饋，每 2 週迭代一次 UI 改進。
給 Feng 的提醒：這個系統的成功指標不是「功能有多完整」，而是「70 歲的阿嬤能不能在 30 秒內叫好貨」。任何讓這件事變複雜的功能，都應該被拿掉。Less is more，在高齡者 UX 中不是口號，是生存法則。
