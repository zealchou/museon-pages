先講決策

技術首選：PhotoMaker V2 + SDXL。 它最貼近這個需求：可直接吃 1 張、也可融合 1–5 張真人參考照；官方明列最低 11 GB GPU 記憶體；對「單張輸入、亞洲臉」宣稱特別改善，並有官方 ControlNet / T2I-Adapter 範例可控制姿勢與構圖。它不需要先替 Zeal 訓練 LoRA，適合先生成多套封面候選。

但不能直接批准商用上線。 PhotoMaker V2 明示依賴 InsightFace；InstantID、PuLID 與 IP-Adapter FaceID 也都使用 InsightFace 的公開人臉模型。InsightFace 官方說明：程式碼可商用，但其公開預訓練模型與相關訓練資料僅限「非商業研究」。所以「repo 是 Apache-2.0」不等於整條生成鏈可用於商業頻道或未來 SaaS。要走商用，先取得 InsightFace 對所用模型的商業授權，或讓法務／工程確認一套有明確商用權重、且能實際替代該人臉 encoder 的方案。在此之前，只能把這些方案當內部概念驗證。

給 Zeal 的白話版：這不是把一張臉硬貼到別人身上，而是先抓住「這是誰」的臉部特徵，再依提示詞重畫成不同表情、服裝、姿勢和背景。用 3–5 張清楚、不同角度的自拍，理論上足以做出一組可挑的 YouTube 封面人像；但每張仍要人工挑選，因為牙齒、手、側臉、眼神和文字背景都可能失真。真正的第一關不是 GPU，而是人臉辨識權重的商業授權。

研究範圍與判讀方法

  • 本報告只做公開資料調查，沒有安裝、下載或執行任何模型。
  • 「最後更新」一律指 GitHub 預設分支的最近一筆 commit 日期，而不是 repo 網頁的 metadata 更新時間；查詢日期為 2026-08-21。
  • 「官方 VRAM」只抄官方 README 明載的數字。若沒有數字，明確寫「官方未公布」；不以社群貼文或其他 GPU 的實測代填。
  • 「品質」優先列官方 demo、論文或官方比較；它們多為作者自評或挑選範例，不當成獨立排名。
  • 本機已知為 NVIDIA GB10、driver 580.159.03、CUDA 13.0、PyTorch 2.9.0+cu130、compute capability 12.1。各候選官方文件多寫較舊 PyTorch/CUDA；本機實際可用 VRAM 仍查無，因此本報告不宣稱任何方案「一定跑得動」。

逐案重點

1. PhotoMaker V2 — 推薦的技術起點，但先過授權關

PhotoMaker 的優勢剛好對應縮圖工作：它不需要先耗時訓練個人 LoRA，能以 ID image stack 融合多張自拍；官方 V2 明說單張與亞洲臉的 identity fidelity 有改進，仍鼓勵多張照片。它亦提供 ControlNet / T2I-Adapter 的姿勢、深度、邊緣控制範例，對「同一人，但換成驚訝表情／思考姿勢／工作室背景」非常實用。

選它不是因為它「宣稱一定最好」，而是因為五者中它同時具備明列的 11 GB 下限、明確多照片工作流、SDXL 擴充控制與為此用途做過的官方比較。先用 3–5 張不同角度、無濾鏡、單人、臉部約佔畫面 20–60% 的照片建 identity stack；若只給 1 張也可以開始，但側臉、笑容和特定表情會更不穩。

不能忽略的反面：其 V2 README 直接說依賴 InsightFace。因此若 Zeal 的目標包含 YouTube 商業頻道或 SaaS，工程排程之前要先走「權重授權確認」；不是安裝時勾選 license 就解決。

2. InstantID — 單張很方便，但官方已把商業紅線寫出來

InstantID 把 identity embedding 和臉部 landmarks 接進 SDXL，單張就能做出不同風格與背景；它也能配 LCM 加速與 Multi-ControlNet。可是官方 README 的 disclaimer 直接寫明：InsightFace face models 為 non-commercial research，InstantID 發布的 checkpoints 也是 research purposes only。這使它適合研究對照，不適合本案的商用候選。

3. PuLID — 畫質與 FLUX 路徑有吸引力，卻增加兩層授權／硬體不確定性

PuLID 是五者中最近仍有功能 commit 的專案，且能接 SDXL 或 FLUX。其 V1.1 官方說明強調在風格、視角、表情、光線改動下保持 ID，也特別列了幾個 SDXL 社群底模；PuLID-FLUX 的 prompt-following 與影像品質潛力高。

但本案不能把「FLUX」當捷徑：PuLID pipeline 使用 InsightFace 的 antelopev2；若選官方常見的 FLUX.1-dev，又會多一個底模非商業授權。即使改 FLUX.1-schnell（Apache-2.0），PuLID 對該組合的官方支援與品質仍未在本次查證中確認。對 GB10 而言，它是第二階段、先解法務和記憶體後才值得評估的路線。

4. IP-Adapter FaceID — 可作歷史基準，不作新建首選

IP-Adapter 是許多工作流的基礎，FaceID Plus V2 有 SDXL 版本，也常能在 ComfyUI 找到整合。但官方 repo 的 FaceID 更新集中在 2023–2024 初，README pin 的 diffusers 也較舊；FaceID weights 未找到清楚可商用 license，還需要 InsightFace。對新 GPU / 新 PyTorch，除錯成本比 PhotoMaker V2 高，沒有抵銷授權風險的獨特優勢。

5. FaceChain FACT — 功能方向相符，工程相容性與權重條款都未清

FaceChain FACT 的「一張、十秒、ControlNet／LoRA 相容」很貼近縮圖素材需求，且專案較晚仍有維護。但官方認證環境停在 CUDA 11.7、PyTorch 2.0 與 A10 24G；它還會串多個 ModelScope 模型。這次沒有取得每一個下游權重的可商用條款，因此只能列為待審實驗候選，不能列為商用替代。

本機已知 CUDA 13.0 / PyTorch 2.9.0+cu130 / SM 12.1，但沒有候選官方文件針對這個組合驗證。GB10 與官方驗證 GPU 不同，且本機可用 VRAM 尚未取得；所以所有「最低 VRAM」僅是候選官方文件的資料，不能推論為本機可跑。

建議的落地路線（不在本次執行）

Gate 0：先決定能否合法商用

  1. 確認用途：只在 Zeal 自有頻道內部用、還是會提供 SaaS／代客服務。
  2. 若有商用可能，先對 InsightFace 詢問 antelopev2 或實際採用 face encoder 的商業條件；同時保存書面回覆。
  3. 建一份「實際檔案清單」：PhotoMaker V2 adapter、SDXL base、VAE、scheduler、ControlNet、任何寫實 checkpoint / LoRA、face encoder。每項記 repo、revision、license、取得日期。
  4. Gate 0 沒過，只可做不對外、不變現的概念驗證；不包裝 SaaS、不拿生成圖作商業縮圖。

Gate 1：隔離式技術驗證

  1. 建立新的 PhotoMaker V2 / SDXL 獨立環境；安裝其 requirements、PyTorch 相容組合與必要的 diffusers / accelerate / transformers。不要改既有 lecture voice pipeline 的 Python 環境。
  2. 下載已審核的 SDXL base 與 PhotoMaker V2 adapter；若需要姿勢控制，再加一個已審核的 SDXL ControlNet。此階段不下載「看到就拿」的 CivitAI checkpoint。
  3. 用一張已獲 Zeal 授權的正面照，固定 1024×1024、batch=1，生成 1 張 smoke test；記錄載入時間、peak VRAM（若可讀）、耗時、CUDA warnings、輸出檔案 hash。
  4. 若成功，再用 3–5 張參考照測 4 組封面 prompt（驚訝、沉思、講解、微笑），每組生成 4 張；不以單一好圖判定成功。

Gate 2：縮圖品質與人像安全驗收

  1. 人工檢查：五官結構、膚色、牙齒、耳朵、眼鏡、手部、側臉、文字留白與是否像 Zeal。
  2. 對每張獲選照片留下 reference set、prompt、seed、模型與版本；這是日後重現、下架或改圖的最低可追溯性。
  3. 生成圖只當「照片素材」。YouTube 標題、箭頭、字級和品牌元素仍由縮圖排版流程處理，不要求生圖模型一次畫對文字。
  4. 若 1–5 張照片仍不穩，不要立刻堆更多控制器；先補拍清楚的側臉、笑容、室內／室外光線，再評估是否需訓練專屬 LoRA。

最終推薦與不選其他方案的理由

選 PhotoMaker V2 + SDXL，條件是先讓 InsightFace 商業權利過關。

  • 相對 InstantID：PhotoMaker V2 更明確支援多張 identity stack，官方最小 VRAM 有數字，且有多圖／姿勢控制的落地範例；InstantID 官方還明寫 checkpoint 僅供研究。
  • 相對 PuLID：PuLID 有更現代的 FLUX 潛力，但對本案反而多了 FLUX.1-dev 非商業、未公開 VRAM 與多張支援未證實等變因。它可當授權後的第二輪畫質 benchmark，不是第一個要施工的方案。
  • 相對 IP-Adapter FaceID：PhotoMaker V2 吸收了更成熟的 identity stack 體驗；IP-Adapter FaceID 的依賴較舊、權重條款較不清，較適合當比較基準。
  • 相對 FaceChain FACT：它的產品方向有吸引力，但本機環境落差最大、下載鏈更長，且權重商用條款尚未逐項確認。

一句話：先把 PhotoMaker V2 做成「有權重授權帳本、可重現、只生人物照片素材」的小型本地試驗；授權未清前，別把任何 Face-ID 開源 demo 當可商用產品。
