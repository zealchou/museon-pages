2023 年 Andrej Karpathy 在一篇 gist 裡描述了「LLM Wiki」模式——把知識的合成工作從查詢時移到攝取時，先編譯、再檢索。這篇文章在 AI 社群引發了「RAG 已死」的討論，但更精確的理解是：

「RAG 與 Wiki 不是對立的，是互補的。語料小而穩定時，先編譯好；語料大且頻繁更新時，RAG 是必要的 fallback 層。兩者加起來才是完整答案。」

— MUSEON 架構哲學，呼應 rohitg00 的 agentmemory v2 論點

MUSEON 從一開始就活在這個結論裡。它的三個核心——記憶系統、路由引擎、技能生態——不是三個獨立模組，而是一個有機的知識迴路。以下，我們逐層打開。

Section 01 · Memory Architecture

記憶系統

MUSEON 的記憶不是「上下文視窗的延伸」，而是一套有層次、有衰減、有演化追蹤的知識積累引擎。

傳統 LLM 應用的最大瓶頸之一是「每次對話從零開始」。即便使用 RAG，大多數系統也只是把文件切成 chunks 存進向量資料庫，查詢時再組裝——這本質上是 Karpathy 批評的 interpreter 模式：每次執行都重新 parse，沒有積累。

MUSEON 的做法不同。它把記憶分為六個層次，不同層次的知識以不同的機制寫入、查詢、更新：

L0 · Working

工作記憶

當前對話的即時上下文。對應認知科學中的 working memory（Baddeley, 1974），容量有限但速度最快。

L1 · Cache

快取層

預編譯的高頻知識——人格摘要、行動規則、使用者狀態。100ms 內完成讀取，無需 LLM 推理。

L2 · Episodic

情節記憶

對話歷史的結構化儲存。每次互動後由觀察者模組（L4）自動寫入，記錄「什麼時候、什麼情境、發生了什麼」。

L2 · Semantic

語意記憶

提煉過的事實與概念，存於 Qdrant 向量資料庫。支援語意搜尋，跨對話的知識可以被精準找回。

L3 · Procedural

程序記憶

已驗證的教訓與行為模式，固化為 Crystal Rules。一旦寫入，影響所有後續決策，不會因對話結束而消失。

L3 · Primal

原型記憶

使用者的深層驅力、八原語能量、決策 Atlas。這是 MUSEON 理解「這個人是誰」的底層基模。

業界獨家：LLM 摘要化攝取（L1 Compile at Ingestion）
MUSEON 的 L1 快取不是簡單拼接字串——它在寫入階段就用 LLM 把使用者互動合成為結構化的人格摘要（persona_digest）。這正是 Karpathy 說的 compiler 模式：知識在進來的那一刻就被處理成可用形式，不是每次查詢時才現算。

知識演化追蹤：supersedes 鏈

傳統記憶系統的致命盲點是「知識只進不出」——舊的認知被新的取代，但舊的依然存在向量資料庫裡，污染搜尋結果。rohitg00 在 agentmemory v2 裡提出了「memory lifecycle + supersedes 追蹤」，MUSEON 的最新版本已實作這個機制：

項目 傳統 RAG MUSEON 記憶系統
知識更新 覆寫或累積，舊知識不會消失 supersedes 有向邊，新知識明確標記取代了什麼
信心衰減 不支援 遺忘曲線機制（規劃中），時間越遠信心分數越低
搜尋品質 純向量相似度，易受舊語料污染 BM25 + Vector + RRF fusion，精準與語意兼得
教訓固化 依賴 system prompt 手動維護 Crystal Rules 自動寫入，永久影響決策
使用者理解 基於對話內容臨時推理 八原語能量圖 + 決策 Atlas 深層基模

混合搜尋（Hybrid Search）已上線
MUSEON 的 soul_ring 記憶搜尋採用 BM25（精確關鍵字）+ Vector（語意相似度）+ RRF（Reciprocal Rank Fusion）三路融合，這與 rohitg00 的 agentmemory 架構完全一致。精準查詢與模糊聯想，不再是二選一。

Section 02 · Intent Routing Engine

路由引擎

每一條訊息到達 MUSEON 的那一刻，就已經開始了一場無聲的意圖判斷——在任何 LLM 介入之前。

現代 AI 系統的成本焦慮很大程度來自一個錯誤設計：所有輸入都走同一條路徑，都交給最貴的 LLM 處理。MUSEON 的路由引擎從根本上反對這個設計。

「先 CPU 後 LLM」——能用規則解決的，不用語言模型；能用向量搜尋解決的，不用生成；能用快取解決的，不用推理。每一層都是防線，也是成本閘門。

這個架構有幾個值得注意的設計決策：

⚡
訊號快篩：零 token 的意圖分類
signal_keywords · CPU-only

在 L2 語言模型介入之前，MUSEON 用關鍵字匹配做第一層意圖分類（quick_signal_scan）。招呼、確認、閒聊這類訊息被直接過濾，L1 主持人自答，不消耗任何推理 token。這不是小優化——對於高頻使用場景，這個設計可以讓 70% 的訊息在不花一分錢的情況下被處理。

🧠
L4 觀察者：從 agent 降級為 CPU 函數
l4_cpu_observer · < 10ms

早期版本的 L4 是一個 Haiku agent，每次對話結束後 spawn 一個新的 LLM 實例處理記憶寫入。v12 架構把它改為純 Python 函數——四步觀察（記憶寫入、訊號更新、偏好偵測、品質調整）全部 CPU 完成，耗時 < 10ms，零 token。這個決策的哲學是：觀察不需要理解，只需要規則。

🎯
模型升降級路由：Sonnet 日常 + Opus 按需
Adaptive Model Selection

MUSEON 的模型使用策略不是固定用最貴的，而是有條件升級。Sonnet 負責所有日常執行；當遇到架構設計、Debug 卡關、DSE 分析、減法決策、Trade-off 仲裁等七類情境時，才 spawn Opus agent 做諮詢，Sonnet 消化後自己繼續執行。Opus 只做諮詢，不直接寫程式。

路由即是品質控制
MUSEON 的路由不只是分流，它同時承擔品質守門的責任。query-clarity 技能在 Skill 路由前攔截模糊問題；荒謬雷達（absurdity_radar）在星座系統裡持續監測不合理的假設前提；PersonaRouter 在群組環境中根據老闆在場與否動態調整語氣與行動優先度。這些都是路由層的能力，不是回覆層的能力。

Section 03 · Skill Ecosystem

技能生態

91 個認知技能模組，不是功能清單，而是一套可以自我生長的能力基因庫。

大多數 AI 系統的「工具」是靜態的——管理員配置好，使用者使用。MUSEON 的技能系統從一開始就設計成可以動態生長：每當系統遇到一個新的複雜任務並成功解決，就有可能自動觸發「技能鍛造」流程，把解法沉澱成可複用的認知模塊。

這個概念對應認知科學中的 程序性記憶（Procedural Memory）——人類學會騎腳踏車之後，不需要每次都重新推導「如何保持平衡」，知識已經固化在身體裡。MUSEON 的技能系統正是讓 AI 建立自己的程序性記憶。

⚒️
即時技能鍛造（ACSF 流程）
Ability Crystallization & Skill Forge

當 MUSEON 完成一個複雜的多步驟任務（≥5 次工具呼叫後找到解法），或在試錯中第二次才成功，或使用者糾正了方法後找到正確路徑——系統會主動觸發技能鍛造，把這次解法凝結成可複用的 SKILL.md 文件，雙邊安裝到 Claude Code 側和 MUSEON Bot 側。技能一旦鍛造，下次遇到類似場景直接調用，不需要重新推導。

🔍
語意路由：用向量搜尋找對技能
Qdrant semantic search · skills collection

當使用者發出請求，MUSEON 不是靠關鍵字匹配找技能，而是先對 Qdrant 的 skills collection 做語意搜尋（limit=3），找到候選技能後讀取完整的 SKILL.md，再決定調用哪一個。這確保了即便使用者的表達方式各異，系統也能找到最相關的認知模塊——而不是依賴固定命令名稱。

🌐
DNA27 親和體系：技能不孤立
Core AI Operating System · 母體 Skill

MUSEON 的每一個技能都有「DNA27 親和對照」區段，描述它與核心作業系統的關係——它依賴哪些基礎護欄，它的輸出如何流回記憶系統，它的行為是否受 ResponseGuard 約束。這讓技能生態不是一盤散沙，而是一個有拓撲結構的知識網路。

Section 04 · Three-Body Resonance

三體共振

記憶、路由、技能，三者獨立強大，但真正的魔法在它們連接之後。

我們用「三體」這個比喻，不是因為它難以預測，而是因為三個系統的相互作用會產生任何單一系統都無法達到的湧現能力（Emergent Capabilities）。以下是六個只有在三者協同時才能實現的獨特能力：

自學習閉環

技能執行 → 路由把結果送到 L4 觀察者 → 觀察者把洞見寫入記憶系統 → 記憶系統更新 Crystal Rules → Crystal Rules 影響下一次路由決策。這個迴路讓 MUSEON 的每次對話都在讓它變得更好。

脈絡感知的技能調用

路由在找技能之前，先讀快取（記憶系統的 L1 層）獲取使用者狀態。同樣是「幫我分析市場」，對創業者和投資人，路由會調用不同的技能組合——因為記憶系統記得你是誰。

技能的累積學習

每一個技能鍛造事件都往記憶系統寫一筆「程序記憶」。隨著技能數量增長，語意搜尋的覆蓋面越廣，路由的精準度越高。系統越用越聰明，不是比喻——是實際的架構保證。

知識衝突的主動解決

當新記憶與舊記憶矛盾，supersedes 鏈讓系統知道「哪個更新」。路由在查詢時會優先使用更高信心分數的知識，過時的判斷不會干擾當下的決策。

並行施工不污染脈絡

多 agent 並行時（不同群組、不同任務），每個 agent 帶著自己的 chat_id 和脈絡，互不干擾。路由確保各 agent 只讀自己需要的記憶片段，不會讓 A 客戶的資訊洩漏到 B 客戶的回覆裡。

降級不失憶

即便 L2 思考者因為任何原因失敗，L1 已經讀了快取，L4 觀察者仍會記錄這次嘗試。記憶系統的寫入不依賴 L2 的成功——失敗本身也是一種被記錄的學習材料。

與業界比較：MUSEON 站在哪裡？
OpenAI 的 Memory 功能（2024）是使用者手動確認的鍵值對儲存，沒有語意搜尋，沒有知識演化追蹤。Mem0 的架構更接近 MUSEON——向量記憶 + 圖結構——但缺乏「程序記憶固化」和「技能鍛造」的閉環。rohitg00 的 agentmemory 在架構哲學上與 MUSEON 最接近，但它是一個記憶引擎，不是一個完整的決策-路由-執行系統。MUSEON 把這三層整合在一個持續運行的框架裡，這是它目前最大的架構差異。

下一步：知識的衰減與信心分數

現有架構有一個已知的待補缺口：Crystal Rules 沒有衰減機制。一條三個月前寫入的教訓，在系統裡的權重和昨天寫入的完全相同——即便情境已經改變。

Ebbinghaus 遺忘曲線（1885）告訴我們，記憶的信心隨時間自然衰減。rohitg00 的 agentmemory 把這個機制應用到 AI 記憶系統：信心分數會隨時間降低，除非有新的互動強化它。MUSEON 的下一個演化方向，正是在 Crystal Rules 和情節記憶上引入這套機制——讓舊知識不是「被覆寫」，而是「自然退場」。

這不只是技術升級，它改變了系統演化的哲學：從「積累」到「代謝」。一個健康的認知系統，不只是持續學習，還要知道如何優雅地遺忘。

設計原則：結構照顧人
MUSEON 的核心價值觀之一是「結構照顧人」——系統的架構本身應該防止使用者犯錯，而不是依靠使用者記住複雜的規則。記憶系統的多層設計、路由的 CPU-first 原則、技能的語意路由——這些不只是效能優化，它們是把「不犯錯」這件事內建到架構裡的方式。

記憶讓 MUSEON 知道你是誰。路由讓它在正確的時機用正確的深度回應你。技能讓它持續積累解決複雜問題的能力。三者的交叉點，是一個越用越懂你、越用越有能力的夥伴——而不是一個每天早上都忘記你昨天說了什麼的工具。

這是 MUSEON 架構的核心賭注：AI 最大的護城河，不是模型本身，而是記憶的品質。
