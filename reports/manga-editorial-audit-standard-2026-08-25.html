把職業漫畫編輯的審稿眼，
轉成手機漫畫報告的驗收表

適用對象：把命理／顧問型長報告製作成「首頁＋分頁＋瀑布流＋圖上文字」的漫畫閱讀網站。目標不是套一層漫畫濾鏡，而是讓讀者在手機上被畫面、文字與節奏自然帶往下一個理解點。

研究範圍：日本商業漫畫的創作與編輯實務，及日本縱向捲動漫畫的媒介轉譯。本文不檢視任何成品，亦不把下列檢核結果當作該雛形的判定。

先給結論：專業審稿不是在看「畫得多漂亮」

日本職業漫畫家與編輯公開談的重心相當一致：讀者是否讀得下去、能否在正確時刻看到正確資訊、情緒是否被畫面的大小與停頓放大。和月伸宏明說，分格與對白位置的目的，是避免讀者不知事件順序與發話時機；助野嘉昭則回顧，職業編輯會看出「先畫圖、再把對白硬塞進剩餘空間」的問題。

最重要的校正：沒有一條跨少年／青年雜誌都通用的「黃金文字比例」或「每頁必須幾格」公式。成熟的編輯判斷是內容、情緒、目標讀者與媒介共同決定的；能被做成硬規則的，是可讀性與構圖安全，不是風格本身。

一、紙本商業漫畫：實際會被審的六件事

1. 視線是否一路被帶走

日漫原稿通常預設右上進、左下出；對白、人物的臉與視線、肢體／背景的方向，共同組成閱讀路徑。編輯不是抽象地問「構圖美不美」，而是找讀序歧義、讀者來回找下一格、或不清楚誰在說話的地方。

2. 大小格有沒有情緒上的理由

大格承擔關鍵資訊、表情、世界或衝擊；小格用於連續動作、細節與加速。古舘春一的說法很直白：大格盡量大、非重點盡量小，兩者折衷反而會平。留白／「間」是時間與情緒的停頓，不是未完成的空處。

3. 對白是否先於畫面被設計

對白框不只是容器，也是最強的視線引導器。編輯會看讀序、說話者連結、文字是否蓋掉臉、手勢、物件或情緒焦點，以及字與背景是否足以一眼判讀。先留對白位置，再作畫，是公開訪談中反覆出現的基本功。

4. 頁尾與翻頁後有沒有「引」與「答」

紙本的左頁末格可丟出懸念，翻頁右上第一格以衝擊、答案或反差回應；這就是「めくり」。章節／單話開頭的扉頁則先建立標題、情緒、主角或本回問題，不應同時背負大量說明。

5. 文字是否替畫面服務

文字多不必然是差；《死亡筆記本》式資訊量高的題材可讓文字成為主角，但仍以「見やすさ」為先。通用警訊是：每一格都解釋、字縮小、或移除圖片後文章仍毫無損失——那表示它更像圖文簡報而非漫畫敘事。

6. 作品世界是否持續同一種呼吸

傳統雜誌原稿以黑白、網點、筆致與角色辨識維持一致；全彩或網頁版則再加上調色、光源、字體和 UI 的一致。這不是要求每格長得一樣，而是讀者不能在沒有敘事理由時誤以為換了一部作品或換了一個時間／情緒。

業界依據：集英社 Jump SQ.「マンガの極意」和月伸宏／助野嘉昭訪談；少年 Jump 漫畫賞「ハイキュー!!」古舘春一與編輯東的分格訪談；週刊 Young Jump 新人漫畫大賞的赤坂アカネーム講評。這些是職業作者與編輯的公開實作語言，而非研究者替作品外加的規則。

二、紙頁語法轉到直向手機網頁，哪些要改

紙本語法手機直向捲動的等價物審計時的重點
右上→左下的頁內 S 型讀序上→下的單一路徑；中文網站不必強行模擬日漫右→左每個螢幕只給一個明確的下一步；避免左右兩端交替的對白／卡片，讓眼睛折返。
頁尾懸念＋翻頁後的揭示「螢幕轉場」：預告、垂直留白／過場、下一個視窗才看見主畫面不是塞一大片無意義空白；留白前後必須形成問答、墜落、停頓或尺度變化。
見開頁一段連續長構圖，或連續兩個 viewport 的視覺關係兩張相鄰圖在手機上不會同時出現，故不能把理解綁在「讀者會看到兩者並列」。
格線與出血內容區塊、段落間距、滿版／留白切換間距是節拍器：同一敘事單位緊、轉場拉開；不等高卡片式地平均切段。
畫在格內的吹出框可在圖片安全區上疊字，也可讓對白獨立放到圖上／圖下的留白若沒有真正的安全區，改成分離式文字，不以半透明黑幕補救構圖。
扉頁章節首屏／封面段只做一件事：提出本章問題或感受，並清楚標示章名；詳解留到下方。

這不是憑空類比。日本縱讀漫畫的實務明確以「上到下、一格一格展開」取代固定頁面；講談社採訪 KADOKAWA タテスク編輯時，也直接把紙本「めくりでドン」轉譯成先以訊號吸引、滑動後才突然出現人物特寫。MangaLab 與 MediBang 的創作指引都提醒：手機縱讀可用高度與空白製造節奏，但對白應更少、字應更大。

三、可直接拿去審的 checklist（手機 390px 實機為準）

標示「媒介規格」者為本研究依職業共識轉譯出的可驗收門檻，不是假稱日本雜誌的統一硬規。每一項先在 390px 寬、100% 縮放、正常亮度下檢查；再以桌機寬度確認沒有因響應式裁切破壞畫面。

  1. 首眼與出口硬性媒介規格
    檢查什麼：每一個畫面單位，使用者第一眼看到什麼、下一步會往哪裡走。
    過關：找不參與設計的人，從每段停留點開始，能在 3 秒內說出「先讀哪句／看哪個主體／下一步往下」；任一段出現兩個同等搶眼又無先後關係的入口，即退回。
  2. 閱讀路徑不折返硬性
    檢查什麼：對白、標題、人物視線、箭頭或裝飾是否讓眼睛無故左右跳。
    過關：將每段文字框中心依實際閱讀次序連線，路徑持續向下，不出現為了讀下一句而橫跨超過內容欄 1/2 寬度又立刻折返的「之」字；例外必須是有意的對峙／對話演出。
  3. 一段一個主鏡頭硬性
    檢查什麼：一個 viewport 是否同時要求讀者理解多個同權重資訊。
    過關：每個約一螢幕高的敘事段有一個主情緒／主結論與一個主視覺；其他元素只能支援它。主標、數據卡與人像三者同時搶第一，判不過。
  4. 大小與留白有節奏，不平均切格硬性
    檢查什麼：連續三至五段是否全部同尺寸、同密度、同間距。
    過關：每個章節至少安排一次有敘事理由的「放大、縮小或停頓」；並能在標註中說明它承擔的是衝擊、資訊、過渡或沉默。只有為整齊而等高的瀑布流卡片，判不過。
  5. 關鍵資訊配得上畫面面積硬性
    檢查什麼：核心結論、命運轉折、讀者必須記住的句子是否被小卡或背景淹沒。
    過關：每章列出一個「本章必看」資訊；它要在一個獨立、沒有競爭文字的畫面單位中出現，或以明確大圖／大字突出。若刪掉非必要裝飾才能看見它，判不過。
  6. 文字與圖片的焦點零碰撞硬性
    檢查什麼：所有疊字框是否壓到臉、眼、手勢、道具、關鍵符號或動作方向。
    過關：每張可疊字圖先標出 focus 區（臉／手／主物件）並外擴至少 12 CSS px；文字框與此區交集必須為 0。沒有安全區的圖，一律把文字移至圖外留白，不以暗色遮罩救援。
  7. 疊字真的可讀硬性可自動化
    檢查什麼：圖片上的文字在真實手機亮度與不同背景明暗下是否仍清楚。
    過關：一般正文與其背後的實際背景對比至少 4.5:1；若背景是不可控照片，文字必須落在原始留白／不透明文字框，而非半透明濾鏡。截圖後以對比工具抽樣每張疊字圖；任一主要段落低於門檻即不過。
  8. 吹出框不變成段落牆硬性媒介規格
    檢查什麼：每一個漫畫式對白／旁白框的行數與句子任務。
    過關：以 390px 呈現時，單框原則 2–3 行、上限 4 行；超過時拆成兩個時間點，或移至圖下正文。單框只傳遞一個語意動作（提問、斷言、轉折或感受），不可同時放背景、分析、結論三件事。
  9. 整段的字量沒有壓扁畫面硬性媒介規格
    檢查什麼：每個有主圖的 viewport 中，文字是否佔據過多畫面或使字級被迫縮小。
    過關：疊在主圖上的文字框總面積不超過可見圖片面積的 25%，正文至少 16px、圖片上重要文字至少 18px；較長解讀改用圖後的閱讀段。這是本案的保守上限，不是漫畫業界的「黃金比例」。
  10. 章節首屏像扉頁，不像目錄硬性
    檢查什麼：新章第一屏是否先設定情緒／問題，而非塞滿結論與導覽。
    過關：首屏只保留章號／章名、1 句引子、1 個主視覺或明確留白；必要導覽可在下一段。讀者若無法說出「這章要帶我去哪種感受或問題」，判不過。
  11. 捲動版的「翻頁」有問答硬性
    檢查什麼：重要揭示前的轉場是否真的延後資訊，使滑動成為節奏。
    過關：每章至少一個關鍵揭示用「前訊號 → 0.5–1.25 個 viewport 的有意義過場／留白 → 揭示」組成；前後能明確指出問題與答案。純粹為拉長頁面的空白，或讀者已在上一屏看完答案，皆不過。
  12. 瀑布流是探索，不是敘事主線情境性
    檢查什麼：卡片瀑布流是否被放在需要嚴格順序的命理主敘事中。
    過關：若內容有前因後果，採單欄固定閱讀路徑；瀑布流只裝用戶可任選的索引、案例或延伸閱讀。任何一張卡的閱讀前提若依賴另一張不保證先看見的卡，即不過。
  13. 色調、字體、光線是一個世界硬性
    檢查什麼：章節與圖片是否無敘事理由地跳換飽和度、光向、線條／水墨密度、字型角色與 UI 色彩。
    過關：建立一張 style bible，寫下 3–5 個主色、正文／標題／對白字體、插畫處理與光線情緒；每章抽三張圖與三個文字模組比對，全部可說明其歸屬。若看起來像不同模板拼接，判不過。
  14. 手機裁切守住人物與動作硬性可自動化＋人工
    檢查什麼：390px、768px、1024px、1440px 下，圖片是否切掉臉、手勢、主道具、或文字安全區。
    過關：四個寬度逐一截圖；所有焦點區完整可見，且文字沒有落到焦點上。單張圖片無法同時滿足桌機與手機時，必須提供不同 crop／不同 source，而非接受其中一端破相。
  15. 可讀性優先於「漫畫感」硬性
    檢查什麼：裝飾框、筆刷、濾鏡、動效是否妨礙讀字或讓讀者誤認可點擊元素。
    過關：關閉圖片後，章節階層與正文仍能順讀；開啟圖片後，畫面加強情緒而不降低可讀性。若需要降低圖片透明度或覆蓋大量黑幕才能讀字，應回頭重作圖文構圖。

四、建議的審稿判定方式

把清單分成兩層，避免「漂亮但讀不下去」被美感掩蓋：

Gate A：阻擋上線

1、2、6、7、8、10、14、15。任何一項不過，都代表讀序、可讀性、焦點或響應式破壞，應先修；它們不是審美偏好。

Gate B：編輯級打磨

3、4、5、9、11、12、13。要求每個決定能說出敘事理由；不靠打勾數量，而看整段是否有呼吸、揭示與一貫的世界觀。

建議流程：先由設計／前端以四個寬度做 Gate A 自檢；再讓不熟內容的人做 3 秒首眼測試；最後由產品負責人以 Gate B 判斷情緒、品味與品牌是否成立。最後一關必須是人審，無法由 CSS 或 Lighthouse 取代。

研究來源與可信度邊界

本報告優先採用出版社官方的職業作者／編輯訪談，並以日本縱讀漫畫編輯與製作方公開資料補足媒介轉譯：

  • 集英社 Jump SQ.〈マンガの極意〉：和月伸宏／中田貴大訪談（可讀性、對白位置、頁尾「めくり」與四角）；助野嘉昭／仲英俊訪談（右上至左下、鏡頭穩定與對白先行）。
  • 集英社 少年 Jump 漫畫賞：古舘春一／編輯東訪談（大小格落差、視線、紙本與手機的相容性）。
  • 週刊 Young Jump 新人漫畫大賞：赤坂アカ的新人ネーム講評（大資訊用大格、格線造成讀序混亂的具體修正）。
  • 講談社 Creators' Lab 對 KADOKAWA タテスク編輯部的採訪（紙本翻頁衝擊如何轉成捲動揭示）。
  • DAYS NEO タテスク編輯講評、MediBang 與 MangaLab 的縱讀創作指引（手機字量、格距、垂直留白與逐格呈現）。
  • 漫畫媒體 Manba 對縱讀形式的分析（低密度、格距、文字／畫面時間差與翻頁效果的類比）。
誠實邊界：「單框 2–3 行、4 行上限」可在 MangaLab 的實作建議找到明確依據；「對比 4.5:1、390px、12px focus padding、25% 疊字面積、0.5–1.25 viewport 轉場」則是把專業共識落成工程驗收的本案規格，不是日本漫畫雜誌公開宣告的統一規則。它們應在實讀測試後調整，而不應被神化為美學真理。
