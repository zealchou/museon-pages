資料範圍：Hugging Face 官方 API 與各 repo 的官方模型卡；未下載、安裝或啟動任何模型。

【結論】

有：截至查證當下，huihui-ai 官方帳號有 2 個針對 Qwen/Qwen3.8-27B 的公開無護欄（abliterated／uncensored）repo；合計提供未量化 safetensors 1 組，以及官方 GGUF 的 25 個主模型檔案變體（另有 1 個 BF16 視覺 projector）。所有單一檔案都低於本機 119.7 GiB 可用統一記憶體，初步判斷可單獨載入；實際仍須保留 runtime、KV cache 與系統記憶體，尤其 262k context 不能由檔案大小保證。

【查證過程】

  1. 於 2026-08-30 直接呼叫 HF Models API：
    • /api/models?author=huihui-ai&search=qwen3.8&full=true&limit=100 回傳正好 2 個官方 Qwen3.8 repo。
    • /api/models?author=huihui-ai&full=true&limit=1000 完整列舉 181 個模型，再以名稱檢查 Qwen3.8／Qwen3-8。其中 Qwen3-8B 是舊的 Qwen3 8B 命名，不能混同於新版 Qwen3.8；本結論只計 literal Qwen3.8 的兩個 repo。
  2. 對兩個官方 repo 分別呼叫含 blobs 的 API，逐一加總 siblings[].size：
    • /api/models/huihui-ai/Huihui-Qwen3.8-27B-abliterated?blobs=true
    • /api/models/huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF?blobs=true 並讀取兩者 README.md 與 GGUF README.md，確認 base model、abliteration 說明、更新文字與未標 WIP 的狀態。
  3. 因已找到官方 Huihui 版本，使用者工作單第 3 步的「若官方沒有才擴大」條件未觸發；但仍對指定常見作者的完整模型清單與精確 search=qwen3.8 做反查：
    • mlabonne：178 個模型；精確 Qwen3.8 搜尋 0。
    • failspy：33 個模型；精確 Qwen3.8 搜尋 0。
    • SicariusSicariiStuff：565 個模型；精確 Qwen3.8 搜尋 0。 三個可重現 API URL 分別為 https://huggingface.co/api/models?author=<帳號>&search=qwen3.8&full=true&limit=100，及同 URL 去除 search、limit=1000 的完整列舉版。
  4. 作為 NVFP4 的有用補充，以 HF 全站 search=Qwen3.8 發現並再以 blobs=true API 驗證 sakamakismile 的第三方衍生 repo。未對其他第三方作者做「所有社群衍生物」的宣稱或窮舉，因官方版本已存在，且使用者規定的擴大搜尋條件未成立。

【沒查到的部分】

  • 未找到 Huihui 官方的 Qwen3.8 NVFP4、FP8、AWQ、GPTQ 檔案／repo；這是對兩個官方 repo 的 API 結果，不是對全 Hugging Face 的否定結論。
  • 原始 safetensors repo 的 config.json 沒有 torch_dtype 值，HF API 的 siblings 也不提供 tensor dtype；因此不能只憑約 55.56 GB 檔案大小把它確定報成 BF16 或 FP16。
  • 「未標示 WIP」只表示本次取得的模型卡／API metadata 沒有 WIP 字樣；不能外推為作者保證穩定或已完成品質驗證。
  • 「可望裝得下」只比較單一模型檔與 119.7 GiB 統一記憶體，沒有啟動實測，沒有估算使用的 runtime、KV cache、context 長度、CPU/GPU 記憶體保留與同機常駐模型。
