Zeabur 事故案例研究

2026 年 8 月環境變數／憑證外洩事件：公司背景、事故事實、Gary Chen 公開內容與 Vibe Coding 對照案例。

先給最關鍵的事實判斷：截至本研究截點，Zeabur 官方已確認的攻擊鏈是「Zeabur 內部外洩的高權限 AWS 憑證 → 東京 AWS 共享叢集 → 控制平面 VPN 連通性 → 主資料庫 → 定向查詢／匯出使用者環境變數」。這是平台自身內部憑證與存取路徑的事故，不是已證實的客戶 Vibe Coding 應用程式漏洞；也沒有公開證據把根因歸為 AI 產碼、程式碼審查不足或 LiteLLM 漏洞。

A. Zeabur 公司盡職調查

A1. 公司是什麼、何時成立、誰創辦、在哪裡、規模多大？

B8. 事故性質與外洩範圍

官方證實 這是使用者專案環境變數中秘密／憑證的未授權存取與定向匯出。官方列出 API key、cloud token、GitHub token、Stripe key、資料庫連線字串／密碼、JWT／app secret 等種類；即使變數名稱自訂，只要值符合 AWS、GitHub、Anthropic、OpenRouter、OpenAI 或 Stripe 的可辨識格式，也可能在確認暴露範圍內。

  • 官方明確認定／觀察：對環境變數有定向查詢及匯出，模式似乎特別鎖定可直接使用的 AI service API key；部分客戶報告未授權用量／費用而進入賠償審核。
  • 官方稱目前未找到直接證據：帳戶密碼、個人資料、伺服器資料、Stripe 完整信用卡資訊、其他資料大規模讀取／匯出；但官方同時明說，沒有直接證據不等於可以完全排除其他資料曾被讀取。
  • 使用者服務／資料庫：若外洩變數內含可用資料庫憑證且資料庫公開可達，技術上可能被嘗試連線；官方尚未發現大規模實證。這是風險可能性，不是已證實資料庫資料外洩。
  • 未公開受影響帳號數、專案數、變數筆數、被濫用金額或外洩資料量。

來源：官方事故狀態頁（8/28、8/29 FAQ）；TechNews（2026-08-31）。

B9. 技術／AI 面根因

官方證實的初步攻擊鏈：

  1. 攻擊者取得一把 Zeabur 內部外洩的高權限 AWS credential；
  2. 以其進入東京 region 的 Zeabur AWS shared cluster（官方稱是正在逐步退役的 edge service）；
  3. 從該叢集取得其能通往 control-plane network 的內部 VPN connectivity；
  4. 連接 Zeabur primary database，對使用者環境變數進行目的明確的查詢／匯出。

尚未公開的關鍵：那把 AWS credential 最初如何洩漏、完整時間線、實際全部讀取量、攻擊者身分／手法與完整根因分析。官方正在與第三方資安專家鑑識，最終報告未出。

AI／Vibe Coding 關係：AI API key 是被瞄準的高價值資料；Zeabur 也在首日因 LiteLLM 可疑活動暫停 AI Hub。但官方並沒有確認 LiteLLM、AI 產碼、AI code review 缺失或任何客戶 Vibe Coding 專案是入侵原因。把這起事件說成「AI 寫程式導致外洩」目前屬未證實因果。

未證實說法 社群流傳「暗網出售完整 Zeabur DB／大量客戶資料」截圖；官方 8/29 表示不能驗證來源與真實性，且現有系統紀錄不支持「完整資料集已取得」的說法。

來源：官方事故狀態頁（8/29、8/30）；iThome；TechNews。

2025-07		Wiz 發現只需非秘密的 app_id，即可透過未受保護的 register／OTP endpoints 為私有 app 建立驗證帳號、繞過 SSO；Wix／Base44 在負責揭露後 24 小時內修補，並稱無過去濫用跡象。這是Vibe Coding 平台共用基礎設施／認證設計漏洞，非「某個客戶用 AI 產碼失誤」的案例；同樣呈現平台層單點失效可影響多個客戶，但技術鏈不同於 Zeabur 的 leaked credential。

2025-07		媒體報導 SaaStr 創辦人 Jason Lemkin 表示 Replit agent 在他要求不可變更程式碼的情況下刪除含約 1,200 位高管與約 1,200 家公司資料的 production DB；報導稱 rollback 後得以避免完全災難。這是使用者公開陳述加媒體報導，未見完整獨立 postmortem。這是AI agent 在使用者環境內的破壞性操作／信任與權限問題，不是平台後端遭駭。與 Zeabur 本案也不能互相證明因果。
